# T113s4 原生启动、进程凭据与租约 · 2026-10-15

C++ 新增 `application-start`，在系统父进程中完成角色、可执行文件及环境预检，再
通过 fork/exec 启动应用。启用该路径必须显式设置
`application_health.launch_receipts_required=true`；正式配置还必须使用原生系统监督
角色。未启用的新路径不改变旧工厂配置的兼容行为。

生产角色固定为网页 UID400、界面 UID401，GID400；必须存在匹配的专用账户。网页
仅保留低端口绑定能力，界面清空能力，均设置 `no_new_privs`。父进程预先准备参数、
白名单环境和凭据结构；子进程等待记录发布、清理继承 FD、重定向日志、降权，再执行
固定程序。执行错误通过独立管道保留步骤和 errno，不自动重试或强杀。

每个角色先发布 root 私有 `*.launch.json`，再发布兼容 PID 文件，然后才允许子进程
执行。记录绑定启动周期、进程出生时间、可执行文件设备号/inode、完整参数、UID/GID、
补充组、能力约束与应用提交。发布使用同步写入和 `renameat2(RENAME_NOREPLACE)`。
停止时记录是主要凭据，即使 current 链接或版本元数据损坏，仍可验证并停止原进程；
记录缺失或被篡改时拒绝退回普通 PID。先清兼容 PID、后清主记录，保留失败状态。

启动与停止共享更新、控制、生命周期锁。更新器执行系统钩子时，仅向显式启用该模式
的原生助手传递已持有锁的描述符；助手核验文件身份并接管同一租约。描述符编号动态
保留，不覆盖 Qt 通信管道；应用执行时关闭所有租约及无关 FD。原生系统监督进程只
参与健康检查，不属于应用启动或停止目标。

主机完整检查运行 222 项，其中 220 项通过、2 项需 root 而跳过；13 项启动专项全部
通过。使用现有 S4 sysroot 编译 ARM 程序，构建隔离网络并隐藏私有配置。
实板完整回归 58 项全部通过，46 次 CLI 观察、实际存储及当前应用只读探测通过。
精确二进制、证据哈希见[结构化回执](validation/2026-10-15-native-launch.json)。

验证程序运行在板上独立目录，正式工厂应用未停止，账户、设备权限、生产启动配置及
信任根未修改。首次测试解包助手因目录创建/断言顺序错误在解包前退出；检查空目录后
修正，没有重传或重放硬件动作。全套最小权限仍需要账户与数据/设备策略、原生监督
迁移及界面通过公开 RPC 获取更新身份。真实 Qt 签名更新、重启回退与实测断电验收
仍属于后续工作，本阶段不授予生产资格。

## 单角色恢复接口（2026-10-24，尚未实板验证）

`application-start ROLE` 可恢复已停止的一个应用角色，例如
`application-stop hmi` 后执行 `application-start hmi`。目标必须是配置中的应用角色；
原生系统监督器不能作为目标。目标 PID/启动记录必须均不存在，遗留记录不会被覆盖。
其他配置角色必须仍存活，并通过原有 pidfd、启动记录、当前应用提交及身份核验；
缺失或不匹配时在 fork 前拒绝。因此此接口用于单角色恢复，不能用于部分冷启动。

该接口沿用原有存储契约、更新/控制/生命周期锁、白名单环境、降权和真实启动记录
发布流程。只预检和启动目标可执行文件，其他角色的 PID 和记录保持不变。
无参数的 `application-start` 仍要求整组应用启动状态为空。
这些核验只是启动时的观察，不能保证其他进程随后一直存活。

新增主机回归验证恢复界面且保留其他进程、错误/缺失同伴记录、遗留目标状态、锁冲突、
非法角色及目标预检失败。主机 development fixture 不等于板端 UID401、真实 HMI
关闭、物理音视频或正式系统更新资格；新接口尚未安装到板端。
