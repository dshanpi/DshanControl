# T113s4 原生降权基础 · 2026-10-15

C++ 新增独立的应用凭据收敛函数，供后续原生启动器在 fork/exec 之间使用。它接受父
进程准备的固定结构，仅用栈空间及 POSIX/内核调用设置 UID/GID、补充组、能力集合和
`no_new_privs`，逐项核验后才返回成功。错误保留具体步骤及 errno。

网页形态仅保留 `CAP_NET_BIND_SERVICE`，为继续使用 80 端口提供条件；界面形态清空
能力集合。能力上限读取实际内核，避免旧工具链头文件漏掉后续能力。拒绝 root 身份、
root 补充组、重复组和无效边界。非 root 调用仅能保留原身份/组并清除能力。

主机完整运行 208 项，206 项通过、2 项需要真实 root 而跳过；另以 root 运行独立
4 项全部通过。实际 ARM 板上的同一 4 项全部通过，共 12 次探针观察。探针在降权后
重新执行自身，再读取内核凭据，并尝试恢复 root、加入额外能力及读取测试私有文件。

| ARM 探针 | UID / GID | 执行后的能力 | 结果 |
| --- | --- | --- | --- |
| 网页形态 | 60000 / 60000 | 仅 bit10，五个能力集合均为 `0x400` | 成功绑定回环 81 端口；权限提升与私有文件访问被拒绝 |
| 界面形态 | 60001 / 60000 | 五个能力集合均为 0 | 81 端口绑定返回 EACCES；权限提升与私有文件访问被拒绝 |

真实、有效、保存及文件系统 UID/GID 均符合目标，补充组仅 60000，`no_new_privs=1`。
数字 UID 只用于隔离测试，没有创建账户。源函数及探针按实际 S4 sysroot 编译，测试包
和证据通过双向 TLS 网络传输并校验哈希。
详见[结构化回执](validation/2026-10-15-native-credentials.json)。

该基础尚未接入真实应用启动，没有改变当前工厂应用、生产配置、账户表或设备权限。
完整启动器还需清理继承 FD/环境、发布私有启动凭据、实现角色权限和生命周期租约，
并完成监督迁移及真实 Qt 升级。当前结果不代表整套最小权限或生产资格已经完成。
