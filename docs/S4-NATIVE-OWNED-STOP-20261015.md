# T113s4 原生进程停止边界 · 2026-10-15

新增 `application-stop [web|hmi|supervisor]`，系统源码的停止及 Web 重启操作改为调用
原生实现。健康检查复用同一套进程身份检查，核对 PID 目录/文件归属和权限、普通单链接
文件、进程 UID、真实可执行文件和完整参数。

停止前先打开内核 pidfd，再检查身份，向绑定的进程发送一次 TERM。全部在册活进程
预检通过后才开始发送信号；每个进程等待退出最多 10 秒。超时保留记录，明确报错，
没有强杀、重新启动或按裸 PID 发送信号的备用路径。清理前再次核对 PID 文件 inode
和内容；测试中被替换的记录保留。缺失记录不会授权猜测进程；返回值统计清除的记录数。

停止不读取应用 installed.json，不创建升级目录，也不要求用户数据库可用。当前实现
仍按 current 可执行路径核对，并要求进程与系统服务 UID 一致；current 链接损坏时会
拒绝。独立启动凭据、非 root 角色及启动/停止共用完整生命周期锁仍在下一阶段。

实际选定厂商 Linux 5.4 的 ARM 系统调用表与实现已核对；板上成功打开自身 pidfd 并
发送零信号。ARM 变参调用明确使用 32 位 pid_t，避免旧工具链上的参数对齐错误。
主机增加 9 项真实子进程测试，覆盖错误进程、同一程序不同参数、非法 PID 文件、锁、
冻结超时、坏应用元数据和退出时替换 PID 记录。

最终主机完整回归 204 项通过；脚本模式保护另有 3 项测试，覆盖五个系统入口。
新 ARM 运行程序的 44 项隔离测试一次全部通过，其中包含原有存储、健康和签名样例
升级矩阵及 45 次升级 CLI 观察。64 MiB 合成工厂初始化本轮耗时 26.17 秒。
测试包和完整证据经过双向 TLS 网络传输及哈希核验；实际 UDISK 和正在运行的工厂
应用只读检查通过。见[结构化回执](validation/2026-10-15-native-owned-stop.json)。

源码还增加了模式保护：已有原生系统配置时，运行程序缺失或不可执行会直接报错并
保留状态。历史无原生配置的兼容入口单独保留，不把原生系统故障当成切换实现的条件。
这部分只有主机执行证据，尚未装入当前板的启动脚本。

当前工厂应用、镜像及生产配置没有改动，没有调用其实际停止操作。整个后续任务仍在
推进：完整原生启动凭据、最小权限、监督迁移、真实 Qt 签名升级和物理掉电验收尚待完成；
生产身份、维护及信任资格保持未验收，自动升级关闭。
