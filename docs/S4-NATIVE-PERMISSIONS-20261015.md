# T113s4 原生角色权限策略 · 2026-10-15

新增 C++ `permissions-plan` 与 `permissions-apply`。计划阶段只读，先核对完整应用
版本树、已知数据项、角色与设备身份，再输出元数据变更计划。应用阶段持有更新和
控制锁；只要保留应用 PID/启动记录，或任何角色 UID 的进程仍存在，就拒绝修改。
不停止进程，不递归修改未知文件；未知数据、孤立的 SQLite 辅助文件、链接、硬链接和可写
应用载荷均拒绝。应用数据内容保持原样。

角色已退出时，保留主数据库对应的已知 WAL/SHM 文件，仅迁移元数据；存在这些文件
不等同于仍有活动进程。恢复交由应用自身 SQLite 完成，权限步骤不打开或修复数据库。

生产身份固定为网页 UID400、界面 UID401，组 dshan-app/GID400。Buildroot 账户表
设置锁定密码和不可登录 shell，不创建主目录。使用选定201902版本真实 mkusers
在隔离暂存目录验证：固定编号、旧账户保留、重复应用及 UID/GID 冲突拒绝均通过。
系统安装器也明确将私有 updater.json 设置为0600。

| 资源 | 所有者/模式 | 用途 |
| --- | --- | --- |
| 应用和公共运行目录 | root:GID400 / 0750 | 两个角色可读取不可变载荷、连接 IPC |
| 私有进程记录目录 | root / 0700 | 应用不能篡改启动凭据或日志 |
| 界面心跳目录 | UID401:GID400 / 0700 | 仅界面写入，系统验证 |
| 应用数据与 EDS 目录 | UID400:GID400 / 0700 | 数据 I/O 由网页业务服务负责 |
| 已知数据文件 | UID400:GID400 / 0600 | 界面通过业务 API 使用数据 |
| framebuffer、具名触摸节点 | UID401:GID400 / 0600 | 界面直接显示及接收触摸 |

设备解析依据固定 S4 板型、唯一 `gt9xxnew_ts` 名称及 sysfs 设备号；不固定 event
编号。实际输入设备的 sysfs 父节点是 virtual/input，不伪造 I2C 祖先关系。通过
O_PATH 固定 inode，再修改其权限，不打开字符驱动执行 I/O；/dev/disp 和终端节点
不授予应用。选定 Qt5.11 linuxfb 源码确认打开 tty 失败只告警，继续初始化 framebuffer。

变更前写入 root 私有尝试日志，记录初始元数据；失败保留已完成数量、阶段和 errno，
不自动回滚或重试。对既有应用/数据/设备的元数据变更前，完整预检已经完成；私有
日志目录和锁属于系统记账。生产应用仍需在升级前备份及停止，不能以计划输出代替。
