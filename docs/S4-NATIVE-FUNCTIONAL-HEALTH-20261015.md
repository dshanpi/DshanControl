# T113s4 原生应用功能健康 · 2026-10-15

C++ 系统程序新增 `application-commit` 和 `application-health`。身份读取不会创建下载、
事务或版本目录；健康检查核对私有 PID 文件、真实进程可执行文件及完整参数、固定回环
API 的应用提交、两个数据库的只读一致性及必要数据表。HTTP 有超时和大小上限，不走
代理或重定向；不回显错误响应正文。既有升级钩子的原始退出码保留机制继续通过测试。

新 HMI 在 GUI 事件循环中验证后端提交后，原子写入权限 0600 的心跳，包含实际 PID、
提交、启动 UUID 和开机单调时钟。健康检查要求归属匹配且不到 6 秒，暂停或卡住的 GUI
不能凭活跃 PID 通过。新 S4 模板采用软件契约 `dshancontrol-platform-2` 并强制此检查；
T153 契约不变。它不代表绘制、触摸或工业总线功能已经验收。

系统启动钩子现在使用私有 umask。仅启动应用时读取提交，坏应用身份不会阻止停止和
恢复；启动身份错误仍立即失败。停止进程、维护及权限模型的进一步原生化另行推进。

主机 186 项和 Qt 36 项测试通过。Qt 测试将实际 GUI 事件循环暂停 6.5 秒并确认心跳
不再刷新。原生系统程序和 HMI 使用 S4 Qt 5.11.3/目标 sysroot 交叉编译；构建期间
禁用网络并隐藏私有配置、SSH 和 Codex 目录。

板上独立目录执行 27 项测试通过：10 项原生健康、15 项原生升级/恢复和 2 项 SQLite
快照测试；原生升级记录有 45 次 CLI 观察。包及证据通过双向 TLS 网络传输并校验哈希。
新 ARM 程序还只读探测了正在运行的原工厂应用，进程、后端提交及两个数据库通过。
见[结构化回执](validation/2026-10-15-native-functional-health.json)。

SQLite 实验备份工具显式关闭源与副本连接，仅对新快照切换 DELETE 日志模式，核验后
同步文件和目录。真实非空 WAL 测试确认已提交行保留、未提交行不混入，副本没有残留
WAL/SHM，旧备份不被覆盖。该工具不安装为生产服务。

已交付镜像及其工厂应用没有改动。当前镜像仍是 platform-1，因此板上真实应用只读
探测没有要求新心跳；新 HMI 的心跳生产端目前是主机 Qt 测试和 ARM 编译证据。
