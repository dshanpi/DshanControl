# 确认硬件、系统与交付物

**适用对象：** 准备在开发板运行或维护 DshanControl 的用户。先核对身份，再选择教程；同属 T113 并不代表镜像、存储和驱动可互换。

## 当前适配范围

| 项目 | 公开源码中的定位 |
| --- | --- |
| T113s4 SD NAND | 当前主要目标；TinaSDK / Buildroot、ARMv7-A softfp、目标 Qt5.11.3 |
| RGB50 / 1024×600、GT911 | S4 文档中有独立开发验证记录；具体硬件修订及完整资格仍需核对 |
| AIC8800D80 | 有 S4 集成与历史网络证据，不能只凭固件文件存在认定联网成功 |
| T153 | 保留历史实现与资料，不把其接口清单复制为 S4 的能力 |
| PC Ubuntu | 用于编译、示例渲染与主机测试 |
| 其他板卡 | 必须单独移植，不能把移植队列写成已支持列表 |

S4 是 **SD NAND**。EinkOS 的 SPI NAND/墨水屏配置不能替换本项目配置。详细来源见 [S4 板级 README](../../boards/t113s4-sdnand/README.md) 和 [硬件输入记录](../../boards/t113s4-sdnand/hardware-inputs.md)。

## 收到设备后记录什么

先记录板卡型号和硬件修订、存储介质、屏幕和触摸型号、系统镜像标识、应用提交、数据卷挂载点。若设备已运行，可在其授权终端执行只读检查：

```bash
uname -a
cat /proc/cmdline
cat /proc/mounts
df -h
```

把结果与该镜像交付清单对应。驱动中的亮度值、framebuffer 抓图和进程存活，分别证明软件侧状态；物理亮屏、触摸位置和音频仍要实看实听。

## 区分三类包

| 收到的内容 | 能做什么 | 不应怎样使用 |
| --- | --- | --- |
| 源码预览压缩包 | 在主机解压、阅读、编译 | 不能交给应用更新器，也不能当固件烧录 |
| 签名应用更新包 | 在满足系统契约和维护条件的系统上更新应用 | 不能夹带内核、DTB、bootloader 或系统库 |
| 完整系统镜像 | 按对应板卡的烧录流程建立或恢复系统 | 不能因名称相似跨板使用；工厂数据分区可能清空数据 |

没有可核验的板型、提交、SHA256 和验证说明时，先向交付方补齐。公开文档不提供“下载最新附件直接刷”的通用步骤。

## 已装系统的首次核对

1. 确认电源与线缆按本板要求连接，保留现有恢复手段。
2. 启动后记录系统标识、应用版本、接口和数据卷状态。
3. 在桌面查看网络与设备数据来源；没有接口时先核对平台声明和驱动。
4. 通过[备份教程](configuration.md)保留配置与业务数据。
5. 需要变更系统时阅读[更新与安装](updates.md)，根据交付说明核对是否清空数据。

一次历史烧录成功不表示当前设备已运行最新源码。本站发布也不会自动更换板端程序。
