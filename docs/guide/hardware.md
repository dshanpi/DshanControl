# 核对硬件、系统与安装文件

在已交付设备上操作前，先确认板卡、系统、应用和数据卷。本页用于选择适用教程，不包含通用烧录步骤。

## 1. 确认板卡和外设

核对板卡标签与交付清单，记录型号、硬件修订、存储介质、屏幕、触摸和供电要求。接口应以实际板卡资料为准。

| 环境 | 当前定位 | 需要另行核对 |
| --- | --- | --- |
| T113s4 SD NAND | 当前主要适配目标，TinaSDK / Buildroot 用户态集成 | 硬件修订、分区、显示、触摸及所需业务接口 |
| RGB50 / 1024×600、GT911 | 有 S4 开发记录 | 当前屏幕连接方式和触摸坐标，不能仅用旧记录判定 |
| AIC8800D80 | 有 S4 无线集成记录 | 本机驱动、固件、接口枚举和关联结果 |
| Ubuntu PC | 主机编译、交互体验和软件测试 | 主机 Qt5 与图形会话 |
| T153 / 其他板卡 | 历史实现或独立移植对象 | 不直接套用 S4 镜像和能力清单 |

S4 使用 SD NAND。名称相近的 SPI NAND、eMMC 或其他板型镜像不能互换。EinkOS 是文档参考，不提供本项目的可替代系统配置。

## 2. 记录正在运行的系统

在**目标设备的授权终端**执行只读检查：

```bash
uname -a
cat /proc/cmdline
cat /proc/mounts
df -h
```

将输出与交付清单中的系统标识、分区和数据卷对应。`uname` 反映内核，不能单独确定应用版本；应用版本应同时记录页面显示值、包清单或交付方提供的源码提交。

检查数据卷是否挂载到预期路径，剩余容量是否足够，配置与媒体文件是否位于独立用户数据区。若挂载状态异常，先处理存储问题，不在该卷上开始保存或更新。

## 3. 确认收到的文件类型

| 文件类型 | 应用场景 | 必查资料 |
| --- | --- | --- |
| 源码预览归档 | Ubuntu 上阅读、编译和测试 | 源提交、许可、SHA256、构建说明 |
| 签名应用更新包 | 通过设备应用更新器安装 | 板型、运行时/ABI、渠道、数据格式、签名和兼容性 |
| 完整系统镜像 | 按板级流程安装或恢复系统 | 板型/存储、分区、清空范围、烧录工具和恢复方式 |

在**保存安装文件的 Linux 主机**，按交付方给出的清单校验。例如清单确实叫 `SHA256SUMS` 时，在该目录执行：

```bash
sha256sum -c SHA256SUMS
```

每个目标文件应显示 `OK`。若没有配套清单，先取得可信来源提供的哈希；仅计算自己的文件哈希无法证明下载完整性。

## 4. 完成首次功能检查

1. 按板级接线和供电要求启动设备，确认屏幕完整显示，触摸位置对应。
2. 打开“全部应用”，进入“系统设置”后返回工作台。
3. 进入“网络通信”，选择实际存在的接口，检查地址与数据来源。
4. 进入“设备监控”，确认外部点位是否已接入；没有数据时记录缺测原因。
5. 按[配置与备份](configuration.md)保留当前布局、配置和业务数据。

页面正常、进程存活和文件可读分别是不同检查结果。物理亮屏、触摸、音频和外接设备应通过实际观察与读回确认。

## 保留设备档案

至少记录：板卡/硬件修订、系统标识、应用版本或提交、数据卷、外设型号、检查日期和结果。后续更新与故障报告使用同一套身份信息。

下一步：[检查网络](network.md)；需要更换程序时先阅读[更新流程](updates.md)。技术依据：[S4 板级说明](../../boards/t113s4-sdnand/README.md)、[硬件输入](../../boards/t113s4-sdnand/hardware-inputs.md)。
