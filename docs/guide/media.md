# 选择本地视频并检查播放结果

**入口：全部应用 → 视频播放。** 本页说明文件选择、播放控制和退出检查。目标设备须已部署与系统匹配的媒体工作进程、Cedar/TPlayer、显示和音频组件；Ubuntu 普通构建可以检查界面与不可用状态，不具备目标板硬件解码能力。

## 1. 准备一个已知兼容文件

将测试视频放在设备上实际可读的目录。默认扫描目录为 `/mnt/UDISK/media`；管理员可在启动 HMI 时通过 `DSHANCONTROL_MEDIA_DIRECTORY` 指定其他目录。

开始时使用已知编码、分辨率和音轨的小文件，记录文件名、编码信息与 SHA256。主机上的路径不会自动成为设备路径，修改扩展名也不会转换编码。

“本地视频”列表的扫描规则为：

- 仅扫描指定目录的直接文件，不递归扫描子目录。
- 列出匹配 `*.mp4`、`*.mkv`、`*.avi`、`*.mov`、`*.ts`、`*.webm` 的可读普通文件。
- 不列出软链接，按名称排序，最多显示 200 个文件。

文件被列出只说明满足文件发现条件，能否播放仍取决于内部编码和后端能力。

## 2. 从文件列表启动播放

1. 打开“本地视频”，点击“刷新列表”。
2. 核对文件名和大小。
3. 点击对应行的“播放”。页面切回“正在播放”，并向播放服务提交打开请求。
4. 等待准备过程结束，检查画面、时间进度及声音。

也可点击“浏览文件”或“打开视频”，选择真实文件后提交打开请求。播放列表中的激活操作同样会打开所选视频。

**从工作台绑定的视频组件进入时行为不同：** 组件只定位保存的文件，提示“已选择绑定的视频，点击播放开始”，需要再点击播放。文件不可用时会保留错误，不自动播放另一文件。

## 3. 检查播放是否成立

依次确认：

1. 页面标题或文件名对应本次选择。
2. “正在准备视频”结束，实际画面出现。
3. 时间进度随播放变化，画面尺寸和编码信息来自服务返回。
4. 有音轨的文件能够按设备预期输出声音。

“CedarX / TPlayer”标签、工作进程存在或请求已受理不能单独证明画面和音频正常。黑屏时保留页面错误与文件信息，不连续重复启动播放器。

## 4. 使用播放控制

| 控件 | 操作方法 | 检查结果 |
| --- | --- | --- |
| 播放 / 暂停 | 点击中央控制按钮 | 图标与状态改变，暂停后进度保留 |
| 上一个 / 下一个 | 在列表范围内切换 | 文件名与实际内容同步变化 |
| 播放进度 | 在后端报告可定位时拖动并松开 | 等待定位完成，进度与画面对应 |
| 音量 / 静音 | 音频能力可用时调整 | 核对实际声音及回读状态 |
| 全屏播放 | 点击全屏控件，再切回 | 控件和画面区域正常，比例符合设置 |
| 画面比例 | “播放设置”选择保持原始比例或适应显示区域 | 核对拉伸、边框和裁切效果 |
| 单个视频循环 | 在播放设置中切换 | 到达结尾后按设置处理 |

灰色进度或音量控件表示当前状态/能力不允许操作，不通过反复点击判断是否有效。

## 5. 离开并返回播放页

切换到“本地视频”“播放设置”或其他应用时，播放器会暂停并隐藏视频，保留当前位置。返回“正在播放”后检查状态，再点击播放继续。

离开页面与关闭媒体进程属于不同阶段。正常关闭整个 HMI 时才会结束其媒体工作进程；在目标设备验收时还需检查没有残留画面、声音或占用。

## 6. 排查常见问题

| 现象 | 检查与处理 |
| --- | --- |
| 列表为空 | 核对扫描目录、挂载、文件名匹配、权限和是否为软链接 |
| 播放器组件尚未安装 | 集成人员检查 HMI 同目录的 `dshancontrol-media-worker` 及其可执行权限 |
| 播放组件尚未就绪 | 核对构建是否包含目标解码能力，及运行库是否匹配 |
| 一直准备或播放失败 | 保存错误码，检查文件编码、媒体后端和显示表面 |
| 有图无声 | 核对文件音轨、ALSA 设备与系统音频配置 |
| 切页后仍有画面或声音 | 记录切页路径、文件、状态和日志，按生命周期故障处理 |

完成一轮“播放 → 暂停 → 继续 → 切页 → 返回 → 退出”检查后，按[验收记录](acceptance.md)保存结果。不要把单一文件播放成功扩展为所有格式支持。
