# 保存显示设置并检查系统服务

通过“全部应用 → 系统设置”修改显示配置、检查服务和操作日志。需要已连接的设备后台；服务启停与重启应在实际允许维护的设备上执行。

## 1. 读取当前显示配置

进入“显示与交互”，等待设备快照和当前设置加载。先记录亮度、刷新周期及演示数据开关，确认页面处于可操作状态。

| 设置 | 页面选项 | 影响 |
| --- | --- | --- |
| 屏幕亮度 | 原始范围 `10..255`，显示百分比 | 亮度配置；实际背光效果还需设备确认 |
| 数据刷新 | 0.5、1、2、5 秒 | HMI 数据刷新节奏 |
| 演示数据 | 开 / 关 | 是否显示对应样例数据 |

字体、语言和布局模式为当前显示信息，不应将只读文字当作可切换选项。演示数据开关不隔离真实控制请求。

## 2. 修改并保存

1. 调整需要的参数；保存前核对所有修改。
2. 点击“保存设置”，检查确认提示。
3. 确认后等待完成，再读取回显值。
4. 检查刷新效果；在目标设备上另行观察实际背光。

本页使用“保存设置”统一提交，与数据上报页的即时提交不同。保存按钮不可用时，先检查快照是否已取得、是否已有请求正在处理。

保存值、驱动读回值与物理亮度是三个观察点。若回显已改变但屏幕没有变化，记录两者差异，再检查原生亮度服务或背光驱动。

## 3. 检查屏幕显示

点击“屏幕色彩 / 比例校验”，在目标屏幕观察边缘、比例、颜色和显示完整性。按校验界面提供的方式退出。

在设备上还应检查触摸位置与实际控件对应。离屏 PNG 或 framebuffer 抓图只能证明软件侧图像，不能代替实际屏幕和触摸观察。

## 4. 操作系统服务

进入服务页，核对目标服务名称及当前可用性。当前入口包括“工业数据采集”“蓝牙连接服务”“网络时间同步”。

1. 确认本次维护允许中断的业务范围。
2. 选择正确服务与启动、停止或重启动作。
3. 核对确认信息后执行一次。
4. 等待返回，刷新服务状态，再检查相关业务是否达到预期。

停止采集会影响后续数据，重启设备会影响全部现场通信。服务返回成功后仍需核对业务效果，例如采集是否产生新数据、时间是否正确。

Buildroot 服务由板级 init 脚本和运行端集成，不直接套用 Ubuntu 的服务命令。

## 5. 查询操作日志

打开“操作日志”，按成功或失败筛选，点击“刷新记录”。页面读取最近 200 条操作记录，重点核对时间、动作、目标和结果。

查找故障时用同一操作时间关联页面结果与日志。记录成功说明对应动作返回成功，不自动覆盖后续设备状态或外部业务结果。

| 异常 | 检查方向 |
| --- | --- |
| 设置按钮不可用 | HTTP API、当前快照、待处理请求 |
| 设置回显异常 | 本次请求结果、配置路径、权限及是否存在其他修改者 |
| 服务不可用 | 当前系统是否包含对应 init 脚本和角色集成 |
| 服务动作失败 | 首个失败信息、脚本输出和业务依赖 |

应用更新操作见[更新教程](updates.md)。技术依据：[系统设置页面](../../components/hmi/src/mainwindow.cpp)、[设置与审计接口](../../components/web/hmi_api.py)。
