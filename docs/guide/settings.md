# 调整显示、查看服务和日志

**目标：** 修改当前设备的显示配置，并能核对服务操作的实际结果。

## 显示与交互

进入“系统设置 → 显示与交互”。当前源码提供亮度、数据刷新间隔、演示数据开关和屏幕校验入口。

1. 先确认页面已经获取到设备快照。
2. 调整亮度；源码数值范围为 `10..255`，UI 同时显示比例。
3. 选择刷新周期：`0.5`、`1`、`2` 或 `5` 秒。
4. 核对演示数据开关用途，真实业务检查时不要用它代替采集。
5. 点击“保存设置”，确认参数后等待结果。
6. 重新读取页面，检查保存值和设备实际效果。

这里需要“保存设置”；与[上报页面](cloud.md)中直接提交的开关行为不同。保存期间或后端不可用时，相关按钮可能禁用。

“屏幕色彩 / 比例校验”用于显示测试图。观察边缘、比例、颜色和触摸对应关系；驱动读回的亮度是配置值，不是物理亮度测量。

## 服务管理

页面包含采集、蓝牙和网络时间等服务入口。先查看是否可用，再选择启动、重启或停止。停止采集会中断数据链路；整机重启会中断全部现场通信。

执行前核对服务名与影响，完成后查看服务状态和操作日志。没有接入现场维护许可时，不以 UI 确认框替代系统门禁。

Buildroot 的服务由 init 脚本和原生运行端管理；Ubuntu 的 systemd 仅适用于主机自己的环境，不是板端的通用控制方法。

## 操作日志

打开“操作日志”，按成功或失败筛选，使用“刷新记录”获取最近记录。页面显示最近 200 条操作信息，重点核对时间、动作、目标和结果。

记录成功只说明对应动作的返回状态。比如网络配置返回成功之后，还需要检查地址和实际连通性；告警确认成功不代表故障消失。

## 应用更新

设置中的更新页和抽屉更新入口指向应用更新能力。检查、下载与安装分开进行；完整流程和拒绝原因见[应用与系统更新](updates.md)。
