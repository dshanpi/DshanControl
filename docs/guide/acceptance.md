# 记录功能检查与验收结果

本页提供复用的检查顺序和记录模板。按本次实际部署范围选择项目，未执行项明确标为未运行；软件测试、主机渲染和目标设备功能分别记录。

## 1. 固定本次检查对象

记录完整应用提交、系统镜像/应用包标识与 SHA256、板卡和硬件修订、工具链/Qt 版本、配置版本、检查时间及操作人员。

在运行前确定哪些业务包含在本次交付中，以及需要哪些从站、账号、媒体文件和外设。没有对应资源的项目保留未运行及原因。

## 2. 按依赖顺序检查

| 顺序 | 检查项目 | 可观察的通过条件 |
| --- | --- | --- |
| 1 | 启动与存储 | 系统和应用身份匹配，数据卷正常挂载且符合写入要求 |
| 2 | 显示与输入 | 实际屏幕完整显示，触摸/输入对应正确 |
| 3 | 桌面与布局 | 应用进入/返回正常，保存后重新加载一致 |
| 4 | 网络与时间 | 接口、地址、路由、DNS 和业务 TLS 正常 |
| 5 | 采集与趋势 | 点位来源明确，数值/单位和独立参考一致 |
| 6 | 告警 | 同一 ID 确认状态更新，导出与页面范围一致 |
| 7 | 现场总线 | 参数匹配，真实从站响应和读回符合预期 |
| 8 | 云/家庭/语音 | 分别取得服务端接收、设备读回及实际录放音结果 |
| 9 | 媒体 | 画面/声音、暂停/继续、切页/退出结果符合要求 |
| 10 | 更新与恢复 | 运行身份、健康、保数据和回退按适用合同完成 |

主机体验可完成相应的软件项目；物理屏幕、从站和外部服务必须在对应环境验证。

## 3. 覆盖失败与恢复路径

在批准的隔离或维护环境中检查所需异常，例如服务离线、无效绑定、文件不可读、数据过期、更新不兼容。验证页面能给出准确状态，恢复条件满足后能继续使用。

只安排本次验收所需的故障注入。涉及断电、存储故障和控制设备时，必须使用该设备适用的测试流程和恢复准备。

## 4. 填写一条结果

```text
检查编号：
检查对象：板卡 / 系统 / 应用提交
功能与场景：
前提与输入：接口、设备、文件、配置版本
操作步骤：
预期判据：
实际结果：
结论：通过 / 失败 / 跳过 / 未运行
证据：日志、截图、任务 ID、文件 SHA256
异常及恢复：
检查人 / 时间：
```

结论按证据填写：

- **通过**：本条预期判据均已观察到。
- **失败**：已执行且不满足判据，保留首个失败及后续恢复结果。
- **跳过**：测试工具或流程因明确条件跳过，记录原因。
- **未运行**：没有执行，不使用其他环境的结果补填。

## 5. 归档并确定交付范围

汇总通过、失败、跳过和未运行项目，列出剩余限制及对应影响。持续运行测试保留连续时间和原始记录，不把中断的多段运行拼接为单次长期稳定性结果。

历史证据只用于对应版本和环境。修改版本、系统或配置后，应重新评估受影响项目，不能将原结论直接移到新身份名下。

公开预览的已有状态见[版本范围](versions.md)，正式交付要求见[发布规则](../RELEASING.md)。
