# 按故障现象定位问题

先保留现场状态与首次错误，再按“环境 → 进程 → 接口 → 数据 → 业务结果”定位。不要将重复重启作为默认排障步骤，以免丢失信息或中断其他业务。

## 1. 保存最小故障记录

记录发生时间、操作入口、目标对象、预期结果、实际提示、系统/应用版本及能否稳定复现。开发主机还应记录工作目录、命令和退出码。

在**源码仓库根目录**记录开发身份：

```bash
git rev-parse HEAD
git status --short
/usr/bin/qmake -v
python3 --version
```

在**目标设备**按需读取：

```bash
uname -a
date
df -h
cat /proc/mounts
ip addr show
ip route show
```

## 2. 处理编译或启动失败

| 现象 | 先检查 | 处理后验证 |
| --- | --- | --- |
| 缺少 Qt 模块 | qmake 路径、Qt5 开发包 | 重新 qmake 与编译，得到可执行程序 |
| 编译器/库架构不一致 | 是否混入 ARM SDK 与主机库 | 使用一致工具链重新构建 |
| 找不到显示 | 当前是否为图形会话 | 图形终端运行窗口，或离屏渲染 |
| 字体加载失败 | 字体资源、构建输出和许可资源完整性 | 程序启动且中文正确 |
| 程序退出或崩溃 | 首个 stderr、退出码、动态库匹配 | 复现同一动作并确认不再退出 |

完整环境步骤见[快速开始](quickstart.md)。不要只截取最后一行构建失败摘要，应保留第一处具体错误。

## 3. 区分两条后台连接

系统、网络、设置、告警等页面使用本机 HTTP API；云、家庭、语音及桌面数据使用 desktop Unix socket。一个服务正常不代表另一个服务已连接。

已部署设备具备 curl 时，在**设备本机终端**检查：

```bash
curl --fail --silent --show-error http://127.0.0.1/api/health
curl --fail --silent --show-error http://127.0.0.1/api/hmi/v1/snapshot
```

确认 HTTP 成功且返回预期 JSON，再检查具体字段。HTTP 200 只说明请求成功，空业务数据仍需排查来源。桌面 IPC 按[只读快照实验](desktop-service.md)检查 socket、文件权限与对端 UID。

## 4. 按页面缩小范围

| 现象 | 定位顺序 | 详细处理 |
| --- | --- | --- |
| 布局保存失败 | 实际目录 → 卷可写 → 所有者 → 并发编辑 | [工作台保存](widgets.md) |
| 数据缺测或过期 | 数据源 → 点位映射 → 时间 → 质量 | [读数与趋势](monitoring.md) |
| 告警无法确认 | 当前选中项 → 状态 → 后端 → 请求结果 | [告警处理](alarms.md) |
| CAN / 串口不可用 | 板级能力 → 驱动 → 接线 → 通信参数 | [总线联调](fieldbus.md) |
| 网络图标正常但业务不通 | 路由 → DNS → 时间/TLS → 授权 | [网络检查](network.md) |
| 云设置灰色 | 服务连接 → 持久目录 → 回读状态 | [云与上报](cloud.md) |
| 家庭控制结果未知 | 网关返回 → 实体设备读回 → 最新授权 | [家庭操作](home-voice.md) |
| 视频黑屏 / 无声 | 文件 → worker → 解码 → 显示/音频 | [媒体播放](media.md) |
| 应用更新拒绝 | 身份 → 签名 → 契约 → 维护 → 健康 | [更新流程](updates.md) |

## 5. 处理“已提交但结果未知”

连接断开可能发生在服务执行之后。先记录请求目标和时间，再读取当前对象状态；更新操作查询原任务，告警查同一 ID，家庭控制查同一设备属性。

只有确认当前状态与允许的重试策略后才重新执行。不要用新的请求覆盖旧任务状态，也不要将前一次成功结果当作本次完成。

## 6. 提交可复现的问题报告

按以下格式提供最小信息：

```text
环境：板卡/硬件修订，系统标识，应用版本或完整提交
操作位置：主机或目标设备，界面入口或终端目录
前置状态：网络、数据源、服务及相关配置是否已就绪
复现步骤：1. ... 2. ... 3. ...
预期结果：...
实际结果：原始提示、退出码或任务状态
出现时间与频率：...
附件：脱敏日志、相关截图、测试文件信息和哈希
```

附上必要日志片段，去除密码、token、绑定码和私有设备信息。不要直接上传整份凭据配置、用户数据库或板卡备份。

问题解决后复现相同步骤，记录具体成功判据，再按[验收模板](acceptance.md)保存结果。
