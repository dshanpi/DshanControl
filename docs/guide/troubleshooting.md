# 按现象定位常见问题

先确定问题发生在**文档站、主机程序还是开发板**，再检查对应层。不要用重装或刷机替代定位。

## 主机编译与运行

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| 找不到 qmake / QtCharts | `qmake -v`、开发包 | 安装快速开始列出的 Qt5 包，显式指定主机 qmake |
| 无法连接 display / xcb | 是否纯 SSH、是否有图形会话 | 无屏环境用 `offscreen --desktop-render`，窗口在图形会话打开 |
| 字体加载失败 | 仓库资源是否完整、qrc 构建输出 | 保留仓库字体和 OFL，不用缺字系统字体掩盖问题 |
| 测试 Python 不存在 | `.test-venv/bin/python` | 在根目录运行 `make test-bootstrap` |
| Unix socket 路径过长 | 临时目录与路径长度 | 使用短的测试目录；不修改生产 socket 规则 |

## 窗口正常但业务不可用

先查看本机 `/api/health` 和 `/api/hmi/v1/snapshot`；再核对 desktop socket、服务端 UID、私密配置权限及业务授权。UI 可运行与业务服务正常是两个条件。

不要把 `127.0.0.1` 改成随机设备 IP，或删除本机访问限制来“修好”测试。主机独立体验没有后台时，未配置状态是预期。

## 工作台保存失败

核对实际数据目录、挂载为可写、运行用户权限。出现并发修改提示时重新加载；格式不兼容时保留原文件。恢复默认前查看是否有需要保留的自定义布局和图片绑定。

## 实板黑屏、触摸或音频异常

把应用日志、驱动状态、framebuffer、物理屏幕观测分开记录。软件显示 backlight 已开启不证明 LCD 发光，抓图也不证明手指触摸正常。

先核对本板屏参、供电、连接与输入设备；不沿用另一板卡的设备节点、采样率或私有库。媒体单次正常不替代生命周期和长期测试。

## 网络和云问题

按接口 → 地址 → 路由 → DNS → 时间 → TLS → 业务授权 → 代理确认的顺序检查。系统时间错误会影响证书和日志排序。云绑定和家庭授权分别核对。

## 更新问题

记录当前任务 ID、阶段、错误码、目标包与系统身份。结果未知时先查询状态，不重复提交。下载成功而安装禁用时，重点看兼容性、签名、数据卷和维护检查。详见[更新教程](updates.md)。

## 文档站问题

- **直接打开 HTML 搜索不可用：** 静态站需要 HTTP 服务，使用 `npm run preview`。
- **图片或子页 404：** 核对 `/DshanControl/` base 和部署产物，运行 `npm run build` 的链接检查。
- **中文乱码：** 源文件使用 UTF-8，检查发布文件而非终端默认代码页。
- **页面仍旧：** 先确认 Actions 对应提交部署成功，再刷新浏览器；不要把构建成功当作部署成功。

## 提交可复现报告

提供应用/系统完整提交、板型、发生步骤、预期/实际、错误阶段、相关脱敏日志和时间；截图注明主机渲染还是实板。不要公开 token、密码、私钥、完整用户数据库或设备备份。
