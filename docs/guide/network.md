# 检查网络接口并恢复业务连接

按接口、地址、路由、DNS、时间和业务服务的顺序检查连接。入口为“全部应用 → 网络通信”。

## 1. 查看有线或无线接口

1. 选择“有线网络”或“无线网络”。
2. 点击“刷新接口状态”，等待当前接口列表。
3. 选择一个接口，核对下方接口名称、IPv4 地址、链路状态和数据来源。
4. 接口消失后重新选择实际存在的接口，不继续使用原详情判断。

当前页面以状态查看为主，不提供完整的 Wi-Fi 扫描、密码配置或静态地址编辑流程。网络参数应按当前系统的配网工具和交付说明设置。

## 2. 从设备终端分层检查

在**目标设备终端**执行只读命令：

```bash
ip link show
ip addr show
ip route show
cat /etc/resolv.conf
date -Is
```

若 BusyBox 的 `date` 不支持 `-I`，使用 `date` 查看时间。

| 层次 | 成功判据 | 不满足时检查 |
| --- | --- | --- |
| 接口 | 对应接口被系统枚举 | 驱动、设备树、固件、硬件供电 |
| 链路 | 有线链路或无线关联符合预期 | 接线、交换机、无线配置 |
| 地址 | 有当前网段要求的地址 | DHCP、静态地址和地址冲突 |
| 路由 | 到目标网络有正确路由 | 默认网关、策略路由、上行切换 |
| DNS | 目标服务域名可以解析 | DNS 服务器与解析服务 |
| 时间/TLS | 系统时间合理，证书校验通过 | NTP、CA、证书有效期和域名 |

如系统具备 `getent`，可用 `getent hosts 服务域名` 检查解析；执行前将“服务域名”替换为实际配置中的主机名。不要用关闭 TLS 校验代替修复时间或证书问题。

## 3. 检查蜂窝配置

蜂窝功能要求模块、SIM、运营商服务、APN 和平台映射均已准备。

1. 打开“蜂窝网络”，核对配置名、控制设备和数据接口。
2. 与系统中的运营商配置对应，确认 APN 与认证要求。
3. 确认允许切换上行后点击连接，等待返回。
4. 再检查接口地址、路由及目标业务连接。
5. 断开前确认当前远程维护不依赖该链路；断开后检查状态。

`ec20a`、`ec20b` 是源码中的配置入口，不代表每块板都安装两路模块。断开操作需要与本次已建立会话对应，缺少匹配会话时应先核对状态，不能强行复用旧句柄。

## 4. 验证目标业务

网络地址正确后，再进入所需页面验证服务：官网绑定检查设备身份和 HTTPS 返回；数据上报检查 MQTT 连接与代理确认；家庭页面检查账号授权和设备同步。

只验证网关或普通网站可访问，无法证明指定业务端口、认证和服务权限正常。

## 5. 按现象继续处理

| 现象 | 下一步 |
| --- | --- |
| 无线接口不存在 | 核对本板驱动及固件；S4 可参考对应 Wi-Fi 启动集成 |
| 有地址但业务失败 | 检查服务域名、端口、TLS 和账号状态 |
| 切换上行后断连 | 核对默认路由与已有连接状态，按系统流程恢复 |
| 页面显示样例接口 | 核对演示设置和数据来源，改用真实接口检查 |

Buildroot 使用板级 init 流程，Ubuntu 主机使用自己的服务管理方式。应按运行系统选择命令，避免直接套用主机 `systemctl`。
