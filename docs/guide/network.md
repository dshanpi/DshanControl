# 检查有线、无线与蜂窝网络

**目标：** 分清接口、地址、路由、DNS 和业务连接，定位“有网络图标但业务不通”的原因。

## 有线与无线页面

打开“网络通信”，分别查看“有线网络”和“无线网络”。选择接口，核对链路、地址等实际返回信息。当前页面主要展示接口状态；不要假定它提供通用 NetworkManager 的全部配网功能。

设备端只读检查：

```bash
ip link show
ip addr show
ip route show
cat /etc/resolv.conf
date
```

| 观察到什么 | 下一步 |
| --- | --- |
| 没有对应接口 | 核对本板驱动、设备树、固件与平台清单 |
| 接口存在但没有地址 | 查接线、无线关联及 DHCP 服务日志 |
| 有地址但访问不到外网 | 查默认路由、网关和网络策略 |
| IP 可达、域名不可用 | 查 DNS 配置及解析服务 |
| HTTPS/MQTT TLS 失败 | 核对系统时间、CA、服务域名和证书错误 |

S4 的 Wi-Fi 启动集成见 [S72dshancontrol-wifi](../../boards/t113s4-sdnand/runtime/S72dshancontrol-wifi)。不同系统的 init 脚本可能不同，按当前镜像说明配网；不要把 Ubuntu 的 `systemctl` 命令直接搬到 Buildroot。

## 蜂窝网络

1. 打开“蜂窝网络”，先等板级能力返回。
2. 核对界面中的配置名、控制设备、数据接口和地址。
3. 管理员按 SIM/运营商要求配置 APN 和认证信息；空配置不是自动适配所有运营商。
4. 确认允许切换网络后点击连接，等待结果并检查地址、路由。
5. 断开前确认当前远程维护是否依赖这条链路。

源码包含 `ec20a`、`ec20b` 配置入口，但不能由此推断 S4 实物具有两路蜂窝模块。设备可用性由板级清单决定。

## 业务上线还要再检查

网络连接成功后，云设备登记、账号授权、TLS、MQTT 代理确认仍是独立环节。先按[云教程](cloud.md)查看设备身份与连接状态，再判断是否已经上报。

保留真实错误；不要通过关闭证书验证、填入演示数据或反复重启整机来掩盖原因。配置密码与私密日志不要放入公开问题报告。

成功判据：目标接口有正确地址和路由，DNS/时间满足业务要求，并且目标服务给出真实成功状态。参考：[网络页面与动作](../../components/hmi/src/mainwindow.cpp)、[蜂窝配置 API](../../components/web/app.py)。
