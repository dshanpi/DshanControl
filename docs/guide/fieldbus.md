# 准备现场总线联调

按本页准备板级资料、通信参数和联调记录，再进入对应协议教程。适用于具备目标总线接口的系统集成人员。

## 1. 确认实际接口与维护条件

先核对板卡硬件修订、收发器、隔离、端子定义、从站型号和接线。页面中存在协议入口，不表示所有板卡均具备该接口。

涉及参数重配、NMT、SDO 写入或周期测试时，按现场要求进入可维护状态，隔离会因命令产生动作的负载。界面确认框只确认本次请求，不能替代现场维护流程。

## 2. 准备通信参数表

| 协议 | 从设备资料取得的参数 | 主机侧准备 |
| --- | --- | --- |
| CAN / CANopen | 仲裁速率、是否支持 FD、节点 ID、对象字典 | 板级 CAN 接口及相应能力 |
| RS485 / Modbus RTU | 站号、波特率、帧格式、寄存器地址/类型/字节序 | 板级串口、采集配置和点位映射 |
| EtherCAT | 从站顺序、ESI/对象字典、允许状态与数据格式 | 唯一映射的主站网口及 SOEM 工具 |

表单默认值是输入初值，实际参数应来自当前网络与从站资料。未知参数应先查明，不通过向设备反复写入猜测。

## 3. 检查页面能力

进入“全部应用 → 现场总线”，选择协议页，查看接口、链路和数据来源。控件不可用或接口列表为空时，先检查平台能力声明与驱动枚举。

本公开基线的界面存在以下范围限制：

- Modbus 页面保存首个从站的部分参数，不包含完整点表配置或运行生效确认。
- EtherCAT 的从站明细和周期图表保留未接入占位，动作结果应结合日志与独立读回检查。
- CANopen SDO 页面是固定四字节整数写入入口，不能直接用于任意类型对象。

这些限制会影响实际操作，具体字段和处理方式在各协议教程中说明。

## 4. 按协议执行

| 操作任务 | 详细教程 |
| --- | --- |
| 配置 CAN 链路、发送 NMT、写入四字节对象 | [配置 CAN 与 CANopen](can.md) |
| 保存串口参数并核对采集结果 | [配置 RS485 / Modbus](modbus.md) |
| 检查主站映射、写入 CoE 对象、执行周期诊断 | [执行 EtherCAT 联调](ethercat.md) |

## 5. 分阶段记录结果

按“接口存在 → 链路配置 → 从站通信 → 业务读回”分别记录。接口 `UP`、命令返回成功和真实从站行为一致不能互相替代。

每次记录至少包含：板卡/系统/应用身份、接口、从站型号、参数、操作时间、返回结果和独立读回。没有从站时，结果只记录为页面或软件校验完成。

完成后使用[验收记录模板](acceptance.md)整理结果。技术依据：[平台与总线操作](../../components/web/hmi_api.py)、[发布要求](../RELEASING.md)。
