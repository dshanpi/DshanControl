# 完成官网绑定并验证数据上报

通过“官网绑定”确认账号归属，再通过“数据上报”验证消息发送。开始前需由管理员完成设备登记、HTTPS/MQTT 配置和凭据部署，并确保网络、DNS、时间及证书正常。

## 1. 检查接入条件

打开“全部应用 → 官网绑定”，依次检查：

| 页面项目 | 继续操作的条件 | 不满足时处理 |
| --- | --- | --- |
| 设备编号 | 与后台登记身份一致 | 由管理员核对 `cloud.device_id` |
| 接入服务 | 能读取当前状态 | 检查桌面服务与 IPC |
| 云端连接 | 显示真实 MQTT 连接状态 | 检查 broker、TLS 和身份凭据 |
| 账号归属 | 可通过查询取得最新结果 | 检查登记接口、授权和网络 |

官网 HTTPS 归属查询和 MQTT 连接是两条独立链路。出现“上次已绑定 · 待查询”时应重新查询，不能用旧状态确认当前归属。

## 2. 查询并使用绑定码

1. 点击“查询 / 获取绑定码”，等待查询完成。
2. 核对返回的六位码和有效时间。
3. 在电脑或手机打开 [100ask 官网](https://www.100ask.net)，登录目标账号，在已开通的设备管理入口输入本机绑定码。
4. 返回设备，再次点击查询，核对账号归属为“已绑定”。

“绑定步骤”按钮可查看页面内说明。实际官网入口和权限以服务方开通情况为准；没有设备管理权限时应联系管理员，不通过重复获取绑定码解决。

有效时间结束后旧码会清除，应重新查询。已绑定设备无需重复登记；官网绑定不会自动授予涂鸦家庭权限。

## 3. 核对上报点位

进入“数据上报”，逐项检查“点位、读数、来源、质量”。选一个有独立参考值的点位，确认单位、数值及更新时间合理。

页面显示过期或 `--` 时，先修复采集和映射。没有有效点位、MQTT 未连接或已有请求等待确认时，“立即上报一次”不可用。

## 4. 配置自动上报

自动上报配置要求后台具备私有持久目录 `state_directory`。该目录未就绪时，开关和周期控件会禁用，服务也会拒绝配置请求。

1. 核对目标设备与上报业务允许的频率。
2. 选择“每 30 秒”“每 60 秒”或“每 5 分钟”。
3. 根据需要切换“启用上报”。
4. 等待服务刷新，核对回读的开关和周期。

**修改开关或周期会立即提交，没有额外“保存”按钮。** 配置成功后写入持久目录中的 `reporting.json`。需要验证跨重启保存时，在允许的维护流程中重启对应服务，再读取状态；不要仅凭控件变化判定持久化成功。

## 5. 验证一次完整上报

1. 记录本机设备编号、点位值与检查时间。
2. 点击“立即上报一次”，等待“等待 MQTT 代理确认”结束。
3. 检查“最近代理确认”是否更新。
4. 在服务端设备管理或业务系统查询同一设备、点位和时间的数据。
5. 将本机返回、代理确认和服务端接收结果分别记录。

MQTT broker 确认表示代理已接收消息；数据库入库和业务消费需要第 4 步验证。`delivery_unknown` 表示结果不确定，应先核对代理和服务端，再决定是否重发。

## 6. 按失败阶段排查

| 现象 | 优先检查 |
| --- | --- |
| 待设备登记 / 查询按钮灰色 | 设备身份、接入服务和 `cloud` 配置 |
| 无有效绑定码 | HTTPS 地址、凭据、证书、响应身份与时效 |
| 已绑定但 MQTT 离线 | broker 地址、端口、CA 和设备认证 |
| 上报设置灰色 | `state_directory` 的路径、所有者和权限 |
| 点位为空或全部过期 | 本地采集、主题映射、样本时间和质量 |
| 代理确认更新但服务端无数据 | 服务端消费、路由、入库和查询时间范围 |

配置字段见[服务配置](configuration.md)。技术依据：[云页面](../../components/hmi/src/cloudpanel.cpp)、[绑定与上报处理](../../components/desktop/src/providers.cpp)。
