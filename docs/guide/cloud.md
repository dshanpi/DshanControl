# 完成云绑定与数据上报

**前提：** 管理员已为设备登记合法身份，并配置云 HTTPS/MQTT 参数和私密凭据。仅有 Qt 页面或网络连接不足以启用云业务。

## 1. 确认连接条件

先核对网络、DNS 与系统时间。后台服务需要能连接配置的云服务，并且设备 ID 必须是登记的真实身份。不要自行编造 ID、绑定码或 API 地址。

进入“云绑定”，观察设备编号、云端连接和账号归属。出现“待设备登记”或“尚未配置”时，应由管理员完成后台配置，不能靠反复点查询生成真实账号能力。

## 2. 获取并使用绑定码

1. 点击“查询 / 获取绑定码”。
2. 等待返回六位绑定码和剩余有效时间。
3. 按页面“绑定步骤”提示，在 [百问网](https://www.100ask.net) 登录自己的账号，在实际可用的设备管理入口输入本机绑定码。
4. 回到设备再次查询，核对账号归属状态。

官网入口与服务开通情况以实际账号为准；源码中的接入合同不保证每个账号已经具备设备管理权限。已绑定设备无需重复登记。过期绑定码会清除，应重新获取，不能重用截图中的码。

绑定接口会核对设备身份与返回时效。云绑定和家庭账号授权是两件事，不要把“官网已绑定”理解成家庭设备已授权。

## 3. 检查上报点位

进入“数据上报”。查看点位、读数、来源和质量，确认这些来自真实采集。缺测和过期读数不会自动填零；如果列表为空，先排查本地采集和点位映射。

## 4. 设置上报频率

支持的周期为 **30 秒、60 秒、5 分钟**。调整“启用上报”开关或周期会直接向服务提交配置；页面没有额外的总保存步骤。不要以为改完但未点击“保存”就不会影响上报。

配置是否跨重启保留取决于后台的私密 `state_directory`。有持久目录时写入 `reporting.json`；没有时不能据本次状态宣称已经永久保存。

## 5. 做一次上报检查

点击“立即上报一次”，等待返回，观察“最近代理确认”。这个时间代表 MQTT broker 的确认，不能替代云数据库入库或业务消费验证。需要端到端验收时，再在服务端核对同一设备/点位/时间的数据。

| 问题 | 检查方向 |
| --- | --- |
| 绑定码不出现 | 设备登记、HTTPS 地址、凭据权限、证书、服务器响应 |
| 已绑定但 MQTT 离线 | broker 地址、CA、端口和设备认证 |
| 有点位但无代理确认 | 上报开关、数据时效、连接状态和请求结果 |
| `delivery_unknown` | 结果尚不确定，先查代理和服务端，不直接认定失败后重复发送 |

配置来源见[后台与数据配置](configuration.md)；实现依据：[CloudPanel](../../components/hmi/src/cloudpanel.cpp)、[后台 provider](../../components/desktop/src/providers.cpp)。
