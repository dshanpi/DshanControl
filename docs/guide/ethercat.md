# 检查 EtherCAT 映射并执行诊断

**入口：全部应用 → 现场总线 → EtherCAT。** 适用于已部署主站工具、具备独立总线网口和已知从站的联调环境。先完成[总线准备](fieldbus.md)。

## 1. 确认主站网口

按系统集成资料检查平台映射。当前动作后端要求 `ethernet` / `ethercat` 对应**唯一一个接口**，并使用 `/usr/bin/omnigate-ethercat` 执行操作。

在**目标设备终端**可只读检查：

```bash
ip link show
ls -l /usr/bin/omnigate-ethercat
```

将接口、工具与当前系统交付清单对应。不要把正在承载远程维护的普通网络接口直接作为总线测试口。接口映射不唯一或在确认期间变化时，应停止操作并核对系统配置。

## 2. 准备 CoE 对象参数

CoE SDO 用于访问从站对象字典。先查从站资料，确认目标对象、允许状态、字节长度及含义。

| 字段 | 页面约束 |
| --- | --- |
| 从站 | `1..65535`，实际编号来自当前拓扑 |
| 索引 | `0..65535`，允许 `0x` 十六进制输入 |
| 子索引 | `0..255` |
| 数据 | 1～32 字节，每字节两个十六进制字符，字节之间用空白分隔 |

表单初值 `0x6040`、`06 00` 可能影响驱动状态，不是通用安全测试值。应替换为经过现场批准的对象和值，按从站要求确定字节序。

## 3. 提交写入并读回

1. 核对主站接口、从站编号与对象参数。
2. 点击“CoE SDO 写入”，复核确认信息。
3. 等待动作结果，保留返回信息和时间。
4. 使用当前系统支持的从站诊断方式读取同一对象及状态，确认实际结果。

页面没有通用对象读回功能。写入返回与读回一致应分开记录；失败或结果不确定时，先确认设备当前状态，再决定下一步。

## 4. 执行一次周期诊断

确认现场允许诊断后，点击“执行 1000 次周期测试”。页面请求固定为 **1000 次、设定周期 1000 微秒**。名义周期总量约为 1 秒，实际耗时取决于主站和现场响应。

等待操作结束，检查动作日志与工具返回结果。需要评价周期质量时，使用实际测量输出中的周期、抖动和错误信息，而非按钮中的设定值。

当前公开页面的从站明细、周期图和“最新周期 / 最大抖动”仍有未接入显示项。“未测量”不能换算为 0，也不能用一次工具成功返回宣称实时性能合格。

## 5. 排查失败

| 现象 | 处理方法 |
| --- | --- |
| 控件不可用 | 检查能力声明、唯一接口映射和数据快照 |
| 工具不存在 | 检查交付系统是否包含匹配主站工具，按系统构建流程补齐 |
| 找不到从站 | 核对供电、链路方向、线缆和真实拓扑 |
| SDO 拒绝或超时 | 核对对象权限、长度、字节序和从站状态 |
| 周期失败或波动大 | 保存输出，检查负载、调度、链路与从站行为 |

完成标准是能够关联接口、拓扑、动作和实测结果。扫描到从站、周期交换完成与控制系统实时资格属于不同验收项目。
