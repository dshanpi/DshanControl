# 保存 RS485 参数并核对 Modbus 采集

**入口：全部应用 → 现场总线 → RS485 / Modbus。** 本页保存首个从站的串口参数；完整寄存器点表和配置生效方式仍由采集系统管理。

## 1. 准备从站资料

完成[总线联调准备](fieldbus.md)，记录串口通道、从站站号、波特率、数据位/校验/停止位、寄存器地址、功能码、数值类型、字节序和倍率。

串口设备节点存在只说明驱动枚举，不能证明对应端子是 RS485。按板级资料确认收发器、A/B 极性、参考地、隔离及终端配置。

## 2. 核对页面可配置字段

| 字段 | 允许范围 | 作用 |
| --- | --- | --- |
| 端口 | 平台声明为 Modbus RTU 的串口 | 选择真实板级通道 |
| 波特率 | `300..4000000` | 写入首个从站配置 |
| 站号 | `1..247` | 标识目标从站 |
| 轮询周期 | `50..3600000` 毫秒 | 首个从站的采集周期 |

范围校验只说明输入合法，硬件与从站未必支持范围内的所有值。页面不提供帧格式和寄存器映射编辑，应在采集配置中核对这些项目。

## 3. 保存首个从站配置

1. 核对状态条中的链路、从站状态和采集状态。
2. 填写实际端口、波特率、站号和轮询周期。
3. 点击“保存配置”，确认提示中的“首个从站”。
4. 等待返回，保留成功或错误信息。

源码默认配置文件为 `/etc/thingsboard-gateway/config/modbus.json`，可通过 `OMNIGATE_MODBUS_CONFIG` 重定向。后端仅修改 `master.slaves[0]` 的对应字段；模板没有从站时会拒绝保存。

**保存成功只证明配置文件已写入。** 当前页面没有完成采集进程重新加载和运行生效确认。按所交付系统的采集服务流程应用配置，不能假定点击保存后通信参数已切换。

## 4. 检查实际采集结果

在维护条件允许并按系统流程应用配置后：

1. 选择一个已知只读寄存器，确认采集点表使用正确功能码和地址约定。
2. 在采集日志或已接入的数据页面检查是否持续取得新样本。
3. 将数值与从站本机显示或已知参考值比较，核对单位、倍率和字节序。
4. 连续观察若干个轮询周期，记录错误计数与更新时间。

本基线“从站与寄存器”表保留“尚未获取寄存器明细”占位。该空表不能证明串口无响应，也不能当作完整寄存器浏览器；以采集后端记录和已配置点位读数为依据。

## 5. 处理异常

| 现象 | 检查顺序 |
| --- | --- |
| 串口不允许保存 | 核对平台 `serial` / `modbus-rtu` 映射和页面端口 |
| 提示模板没有从站 | 由集成人员准备合法采集模板，再使用页面修改首个从站 |
| 保存成功但仍按旧参数运行 | 检查服务加载的配置路径和系统规定的应用流程 |
| 全部超时 | 从站供电、A/B、站号、速率、帧格式 |
| 有响应但数值错误 | 寄存器地址约定、功能码、数据类型、字节序及倍率 |

多从站配置应在采集系统中分别管理，不通过多次覆盖首个从站代替总线点表。完成后记录保存值、实际运行值和采集结果。
