# 选择更新方式并检查安装结果

先确定收到的是源码、应用包还是系统镜像，再按对应流程操作。应用更新入口为“全部应用 → 应用更新”，也可从系统设置进入。

## 1. 选择正确的交付类型

| 类型 | 包含内容 | 使用位置 |
| --- | --- | --- |
| 源码预览 | 已提交源码、许可、校验与构建资料 | 开发主机解压、编译和测试 |
| 应用更新 | HMI、Web、业务服务及应用资源 | 匹配系统的应用更新器 |
| 系统镜像 | BSP、内核、DTB、基础库、分区及系统集成 | 对应板卡的系统安装/恢复工具 |

`source-*`、`app-vX.Y.Z`、`system-vX.Y.Z--BOARD` 用于区分发布类别。名称只是初步线索，仍须核对清单、签名、SHA256 和适用设备。

## 2. 完成更新前准备

1. 按[硬件核对](hardware.md)记录板型、硬件修订、系统与应用身份。
2. 按[备份流程](configuration.md)保存配置、布局和业务数据。
3. 确认数据卷、空间、供电和恢复方式符合交付要求。
4. 确认设备已经进入真实可维护状态，允许桌面和相关服务中断。

更新器还会检查架构、float ABI、libc、runtime ID、系统契约、协议版本、渠道、公钥及数据格式。`pending` 或身份不匹配时，应获取匹配交付物，不手工修改身份或填空检查脚本绕过。

## 3. 检查兼容更新

1. 打开“应用更新”，记录当前版本。
2. 点击“检查更新”，等待本次检查结束。
3. 核对可用版本、发布摘要和更新前检查项。
4. 打开“查看兼容性详情”，确认目标与当前设备一致。

“无兼容更新”不等于检查失败；“检查未完成”也不能当作没有更新。记录实际状态和错误，必要时检查网络、发布配置和信任公钥。

## 4. 下载并校验

点击“下载更新”，等待下载与完整性校验完成。记录本次下载任务与目标版本。

下载成功后应用仍运行旧版。目标版本或来源发生变化时，应重新检查和下载，不能将旧下载任务作为新版本的安装依据。

## 5. 安装并跟踪同一任务

1. 在前置检查通过、下载完成且维护条件成立后点击“安装更新”。
2. 在确认框复核版本及会中断的服务。
3. 跟踪当前任务的准备、检查、切换、启动、健康检查或回退阶段。
4. 完成后核对最终结果，保留任务 ID 与初始失败原因（如有）。

关闭再打开页面时，应读取已有任务，避免重复发起安装。连接中断不能直接解释为安装失败；先恢复连接并查询同一任务。

## 6. 验证安装或回退

安装成功后检查：实际运行的应用身份与目标一致，桌面能够打开，必要服务恢复，布局与业务数据仍在。根据交付要求另行验证重启后的身份和功能。

健康检查失败时查看是否已恢复旧版。回退本身失败则保留事务日志，使用系统恢复流程；不要删除状态文件后重新安装来覆盖原始证据。

应用事务负责受限载荷、安装锁、切换、健康观察和恢复。应用包不应覆盖内核、DTB、系统库或携带任意安装/迁移脚本。

## 7. 安装完整系统镜像

系统镜像按该板型的独立交付流程操作：核对板型与存储 → 校验哈希 → 确认清空范围 → 备份 → 使用匹配工具烧录 → 检查启动和恢复。

包含空工厂 UDISK 或 `CLEARS-DATA` 标识的镜像可能清空数据。烧录工具完成提示只代表工具阶段结果，仍需验证实板启动、显示、触摸、接口和数据卷。

## 处理常见拒绝

| 拒绝类别 | 处理方法 |
| --- | --- |
| 身份或系统契约不匹配 | 获取针对当前系统构建的包 |
| 签名 / 完整性失败 | 核对可信来源、下载文件与系统公钥 |
| 维护条件不满足 | 按现场流程进入可维护状态 |
| 空间 / 数据卷异常 | 保留数据，按系统存储恢复流程处理 |
| 健康检查失败 | 查看服务日志、运行身份和回退状态 |
