# 查看趋势、点位与告警

**目标：** 判断读数是否可信，完成一条告警的查看与确认。先保证对应采集服务在线。

## 总览与趋势

从“运行总览”了解资源和链路，再进入“设备/趋势”查看点位。显示 CPU、内存等系统数据，不意味着外接传感器已接入；每条外部读数都应有具体设备和点位来源。

查看时依次核对：设备名称 → 点位标识 → 单位 → 质量/时效 → 变化曲线。若界面支持暂停监视，暂停的是当前展示节奏，不应理解成所有采集服务都已停止。

## 读数状态的意义

| 状态 | 正确理解 |
| --- | --- |
| 有效新数据 | 可用于本次观察，但仍需核对单位和量程 |
| 缺测 | 没有可用值，不能按 0 参加计算 |
| 过期 | 曾有数据，但当前时效不满足 |
| 离线 | 数据源或服务不可达 |
| 演示数据 | 用于展示，不属于现场采集证据 |

MQTT 传感器入口要求显式主题映射，保留消息不会被当作实时样本。开发者接入点位时须保留身份、质量和时效；见[API 与 IPC](api.md)。

## 一次告警处理流程

1. 打开“告警记录”，选“全部”“未确认”或“已确认”。
2. 根据级别、来源和时间缩小范围。
3. 选择一条记录，阅读详情并核对对象和发生时间。
4. 按现场流程确认原因后，执行告警确认；等待服务器结果。
5. 重新查看该告警的确认状态，必要时导出记录。

“确认告警”表示记录已被确认，不表示物理故障已经修复。重新出现的故障应按新的事件处理。

筛选后原选中项可能不再可见，此时应重新选择，不能对着旧详情继续确认。后端离线时保留错误，避免把点击动作当成确认成功。

## 导出与复核

用页面提供的导出入口保存当前记录，并核对时间范围与内容。导出文件可能包含现场设备名称与运行信息，分享前先脱敏。数据库持续写入时，不直接复制单个 `.db` 文件当作一致备份；参考[配置与数据备份](configuration.md)。

成功判据：点位有明确来源和时效；告警确认后服务器状态更新；导出内容与选定范围一致。

实现依据：[页面和筛选逻辑](../../components/hmi/src/mainwindow.cpp)、[SQLite 与告警 API](../../components/web/hmi_api.py)。
