# 配置 CAN 链路并操作 CANopen

**入口：全部应用 → 现场总线 → CAN / CANopen。** 开始前完成[总线联调准备](fieldbus.md)，准备实际 CAN 接口、网络速率、节点 ID 和从站对象字典。

## 1. 核对接口与接线

查看“接口状态”表中的接口、链路、波特率和数据来源。确认选择的是目标总线，收发器、CAN_H/CAN_L、参考地和终端电阻符合网络设计。

需要从系统侧检查时，在**目标设备终端**执行：

```bash
ip -details link show
```

找到与页面相同的 CAN 接口。未枚举接口时先检查驱动、设备树和板级清单，不进入参数应用步骤。

## 2. 应用 CAN 参数

| 字段 | 页面允许范围 | 填写依据 |
| --- | --- | --- |
| 接口 | 板级枚举的 CAN 接口 | 当前接线对应通道 |
| 仲裁波特率 | `10000..1000000` bit/s | 总线上所有节点一致 |
| CAN-FD | 仅平台声明支持时可启用 | 控制器、收发器及网络能力 |
| 数据波特率 | 不低于仲裁速率，最高 `8000000` bit/s | FD 数据阶段配置 |

1. 选择接口，输入实际仲裁速率。
2. 网络使用经典 CAN 时保持 CAN-FD 关闭；使用 FD 时再填写数据速率。
3. 点击“应用配置”，核对确认框中的接口。此操作会短暂中断该接口。
4. 确认后等待返回，再读取接口状态。

页面初值 `500000` 和 `2000000` 不代表网络推荐参数。成功后还需与已知从站通信，不能只以接口重新变为 `UP` 判定联调完成。

## 3. 发送 NMT 状态命令

切换到“NMT 控制”，选择接口、节点和目标状态。页面提供 `OPERATIONAL`、`PRE-OPERATIONAL`、`STOPPED`、`RESET`。

1. 核对从站允许的状态转换及当前维护条件。
2. 通常填写单个实际节点 `1..127`。**节点 `0` 表示广播到所有节点**，只在确需广播且已确认影响范围时使用。
3. 点击“发送 NMT”，检查确认框中的节点或广播范围与状态。
4. 等待结果，再通过从站诊断或独立状态读取确认状态变化。

NMT 发送成功不能直接证明从站已进入目标状态。结果未知时先检查从站状态和总线错误，再决定是否重试。

## 4. 写入 CANopen SDO

当前页面使用原始索引写入，不加载对象字典；发送长度固定为 **4 字节、小端整数**。先确认对象确实允许此长度和类型，其他类型应使用匹配的工程工具或完成接口扩展。

| 字段 | 页面约束 |
| --- | --- |
| 节点 | `1..127` |
| 索引 | `0..65535`，支持 `0x` 十六进制格式 |
| 子索引 | `0..255` |
| 写入值 | `-2147483648..4294967295`，按四字节编码 |

按对象字典填写后点击“SDO 写入”，复核目标、类型和含义，确认后等待结果。表单中的 `0x2000` 是初值，不能作为通用测试对象。

通过从站支持的读取工具核对同一对象及相关状态。页面没有与该写入对应的通用 SDO 读回表单，不应把发送返回值当成设备读回。

## 5. 定位常见失败

| 现象 | 优先检查 |
| --- | --- |
| 接口列表空 / 控件灰色 | 平台能力、驱动枚举、快照连接 |
| 配置失败 | 驱动支持的速率、FD 能力、接口权限与运行日志 |
| 接口存在但从站无响应 | 线缆、终端电阻、速率、节点 ID 和电源 |
| SDO 中止 | 对象访问权限、长度、类型及允许设备状态 |
| 返回超时或结果未知 | 先查看同一节点实际状态，避免重复写入 |

完成后保留接口配置、节点、对象、写入值、命令结果与读回。技术依据：[CAN 页面](../../components/hmi/src/mainwindow.cpp)、[CANopen 后端](../../components/web/hmi_api.py)。
