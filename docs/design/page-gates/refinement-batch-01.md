## P14 显示与交互
业务流程：读取服务记录 → 编辑表单 → 保存确认 → 设置结果字段核对 → 自动提交背光应用 → 分别展示结果。取消确认保留编辑。确认期间编辑或连接变化使本次确认失效；重复点击不能新增事务。

操作步骤：
1. 核对分辨率和服务记录，调节亮度、刷新间隔和演示开关。
2. 保存前查看“未保存”提示；点击保存设置，核对确认框列出的实际值。
3. 默认取消；确认后等候保存和背光应用两阶段结果，不把服务记录当作背光已实际改变。
4. 放弃编辑时选择撤销修改，核对恢复目标，默认继续编辑。撤销只恢复完整有效服务记录，不提交控制命令。
5. 使用屏幕色彩/比例校验和查看服务入口；返回或打开本页步骤保留编辑。

真实字段依据 mainwindow.cpp：亮度原始值10–255、按钮步长3，百分比显示；刷新选项500/1000/2000/5000ms；恢复服务记录时可能添加500–10000ms区间中的有效间隔；演示开关布尔值。静态语言/字体/布局不改为可编辑控件。

拟改动：表单与服务记录分栏；未保存状态更突出；主操作与结果固定；撤销确认增加恢复目标摘要；确认框增加两阶段结果说明。上述均未实现。保留分辨率、色彩校验、服务入口及原能力/确认/事务约束；不增加主题/语言/自动熄屏配置，不删原功能。

状态约定：
- 未连接：保留表单，禁用保存/撤销，原操作反馈继续显示；查看服务仍是可用导航。
- 服务记录不完整：显示原因并禁止撤销，不用默认值冒充有效记录；保存的既有门禁不随设计擅自扩大。
- 等待：显示正在保存或正在应用背光，禁止重复提交及撤销。
- 回复不匹配/超时：标记结果未确认，不把“未确认”表述为已证明硬件失败；保留原响应校验。
- 撤销确认期间服务记录、编辑、连接发生变化：不恢复表单，提示核对后重新确认。

本次四份选定图：main、confirm_v2、discard、offline_v3。初次确认图背景伪增主题/语言/事件表已废弃；离线v1漏服务导航、v2误将未确认写为失败均保留，v3改正。原始值辅助说明可在最终产品稿中简化为用户可读说明，不把内部数值当作新增设置。

## P11 有线网络
流程：读取接口 → 选择一条 → 刷新 → 查看字段 → 在目标应用验证服务。
字段：接口、状态、IPv4地址、来源，选中详情复核相同四项。保留查询入口并固定到页底；不增加地址配置、ping或自动诊断。地址存在不能判外部服务可达。图中的eth0/eth1/eth2及192.0.2.10都是明确标注的设计示例，不假定实板存在这些接口。
空数据与读请求失败必须分开；若实现保留旧数据，明确标注当前未知。接口消失时清空失效选择与详情。待请求时的反馈必须依据真实读取状态，不用假进度条。
