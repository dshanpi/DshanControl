# 04 数据模型与业务规则

## REQ-DATA-001 数据来源与真实性

|显示对象|真实来源|禁止的替代|
|---|---|---|
|日期/时间|系统QDateTime，明确当前时区|固定14:28用于生产|
|网卡连接|HMI snapshot.networks，平台实际通道映射|把wlan0存在当已联网|
|云在线|desktop cloud.mqtt等服务状态|把LAN/Wi-Fi在线当云可达|
|环境温湿度|授权点位及单位，reporting.points或真实sensors适配|system.temperature冒充环境温度|
|系统温度|snapshot.system.temperature及temperature_source|未读到填0°C|
|总线|snapshot.buses和platform能力/通道|仅设备节点存在就判从站在线|
|告警|snapshot.alarms + GET/alarms|固定“02”或demo alarms|
|家庭开关/亮度|home.devices[].status[{code,value}]|POST accepted立即翻转|
|媒体进度|worker.position_ms/duration_ms|QTimer自己假跑|
|上报确认|reporting.last_broker_ack|等同云业务入库成功|

UI统一ViewModel：`quality=loading/good/stale/unavailable/error`，`source`、`sampledAtUtc`、`receivedMonotonicMs`、`value`、`unit`、`errorCode`。保留来源，数值只有有限数且quality=good才显示实时值；缺失、null、NaN、无穷、未知类型均为“--”。历史缓存值可显示但明确“上次值/已过期”，不能着绿色在线。

desktop provider当前对点位要求UTC时间、sequence增长、质量good，最大60秒新鲜度、128个点/32个设备；过期value=null。UI按provider质量，不延长有效期。家庭权限/能力新鲜窗口当前30秒，命令由服务再次校验。不同来源的TTL不能统一硬编码为60秒。

## REQ-DATA-002 快照调度

全窗口一个HmiClient，复用现有网络管理器异步逻辑；默认1000ms，遵守settings.refresh_ms的500～10000约束，只允许一个snapshot进行中，4秒超时。DesktopClient独立2000ms快照，4秒超时，最多16队列、同类轮询合并；不可为7张卡各起7个轮询器。切后台不停止关键健康心跳，非可见图表停止动画，数据读取可合并但不能阻塞业务操作。

HTTP和本地RPC每次响应校验对象类型、ok和字段范围，使用请求序号/配置revision丢弃过期响应。网络/本地服务断开：只读查询允许退避重连（2/4/8/15秒上限，状态显式）；写操作不自动重放，用户重新明确操作才发新请求。快照与写入结果分流，避免刷新覆盖pending状态。结构大幅不兼容时显示协议不匹配，不能随意toDouble默认0。

## REQ-DATA-003 点位趋势

现有 `/history` 只支持系统cpu/memory/temperature/storage，返回bucket/value；其中temperature不是环境温度。环境趋势本期新增PointHistoryStore：按真实point_id缓存最近30分钟环形序列，采样时间/quality一起存，最多1800点/绑定趋势点；仅收新样本不重复缓存同一snapshot。没有历史服务时先显示“积累中”，**不补生成过去曲线**。跨重启历史若未实现持久化就标注本次会话，不伪造30分钟完整图。

绘制将可视数据降采样到图宽，保留极值/异常断点；时间严格递增，倒序/重复不连线。时间跳变清分段，曲线缺口不插值伪造。只有一个点画点；无点画空态；常量序列上下留最小安全范围防除0。默认°C一位小数、%一位小数；不同点位单位必须使用来源映射。压力量纲不明则“暂无数据”，不推测Pa/MPa。

## REQ-DATA-004 本地布局和配置

新增布局文件建议 `${DSHANCONTROL_DESKTOP_STATE_DIR}/layout-v1.json`；默认目标 `/mnt/UDISK/dshancontrol/data/desktop/layout-v1.json`。这是拟新增路径，安装器/系统生命周期应预置可由HMI UID401写入的目录，不让GUI提权。桌面可以读取状态但不能直接修改其他服务的private配置文件。禁止写进 apps/current 或不可变版本目录。

格式见default-layout.json、layout-schema.json：schema_version、revision、active_page、pages/slots、binding。实例ID稳定且全局唯一，slotId每页唯一；页数v1固定2，slot数每页7；类型兼容矩阵见app/widget配置。未知future schema只读保留原文件，提示版本不兼容，不覆盖。解析上限128KiB；拒绝重复ID、未知type、无效路径/slot和数据类型。布局存储不用QSettings散写替代事务：QSaveFile原子替换，成功后才发layoutCommitted；中断保留旧完整文件。

第一次创建默认文件与布局编辑分开；读取失败不反复覆盖旧配置。恢复默认需用户操作，恢复前留一个有界备份。图片/文件只保存路径与可选hash，不嵌入base64或影片；升级迁移保留用户配置/点位绑定。布局中不存云密码、令牌、家庭密钥。

## REQ-DATA-005 告警与通知

`alarm.id`是正整数主键，展示时间转换本地时区。active/today/recent口径保留服务定义，“待确认”计数必须来自对应状态而非把所有历史记录计入。严重度用文字/图标+颜色双编码，颜色不单独表达结果。网络恢复不自动ack，重复ack响应already_acknowledged也按真实结果处理。不存在404/冲突409时刷新列表并说明，不删除本地记录冒充成功。

通知中心聚合事件用稳定key={source,type,id}去重；断网提醒不每次轮询新增。声音开关只影响提示音，不屏蔽告警，也不改变确认状态。确认动作沿既有审计链；日志不能带绑定码/密钥/私密对话全文。

## REQ-DATA-006 媒体与图片

图片读取放工作线程、按目标框decode/缩放，UI线程仅绘制缓存QImage/QPixmap；限制输入文件大小与解码像素，错误给占位。建议初期JPEG/PNG，最大8192×8192和20MiB，超过提示缩小图片，不能导致桌面内存失控。显示fit/crop配置，原图09固定裁剪方式为视觉验收特例。

v1桌面媒体是海报/缩略图，不承诺多个实时视频窗口或多路解码。参考图为原有UI示意画面，不是摄像头实时流。完整播放器worker缺失/无Cedar时显示未安装/解码不可用；不能报告硬解已确认。hardware_decode_confirmed须遵循实际worker证据，不因编译开关为true。

## REQ-DATA-007 错误状态文案

|状态|主文案|允许动作|
|---|---|---|
|加载首次快照|正在连接/加载中|返回、其他功能|
|未配置|尚未配置|进入对应设置|
|服务断开|服务未连接|用户重试/等待只读重连|
|没有数据|暂无数据|选择点位/查看数据来源|
|样本过期|数据已过期|查看最近时间、刷新只读数据|
|权限失效|账号授权已失效|重新绑定/授权入口|
|命令超时|结果待确认|刷新设备状态，不自动重发|
|功能缺失|当前设备不支持|返回|
|配置写失败|保存失败，原布局已保留|重试/放弃|

所有错误保持卡片尺寸与图标风格。固定fixture不受本机网卡/日期/真实服务影响；真实模式完全不得回退到fixture。
