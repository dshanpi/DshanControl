## REQ-API-010 HTTP HMI 合同

基址当前源码常量 `http://127.0.0.1/api/hmi/v1`，UI发异步本机请求，不连接VM地址作为产品后端。接口已有实现，本次仅抽取客户端，不创建第二套同义API。

|方法/路径|请求|响应核心|消费方|
|---|---|---|---|
|GET /snapshot|无|ok,timestamp,system,platform,summary,buses,networks,cellular,sensors,alarms,services,settings|顶栏、工作台、原应用|
|GET /history|metric=cpu/memory/temperature/storage；hours1..720默认24|ok,metric,points[{bucket,value}]|系统趋势；禁止直接当环境趋势|
|GET /alarms|limit1..500，默认100|ok,alarms[]|告警详情与通知|
|POST /alarms/{id}/ack|空对象|ok,id，可含already_acknowledged|告警确认|
|GET /settings|无|ok,settings|设置初始化|
|PUT /settings|允许字段子集，类型/范围校验|ok,settings|亮度/刷新等设置|
|POST /actions|action,params,confirmed:true|ok,action,result|既有受控动作|
|GET /audit|无|ok,audit[]，最近200条|审计页|

snapshot.system：cpu,memory,temperature,temperature_source,storage,uptime_seconds,hostname,kernel,active_slot。platform：board_id,soc,capabilities,channels。alarms：active,today,recent。services目前含thingsboard/bluetooth/ntp等已声明服务。sensors在非demo且无采集源时可能为空，是有效业务空态。networks按实际板级映射读取，不能硬编码eth0/wlan0存在。

settings中brightness范围10..255，refresh_ms 500..10000，demo_mode bool，page_cycle_seconds 0..300。具体字段名以当前 `_settings`/PUT校验为准；不新增不存在的“Wi-Fi开关”字段。更新应采用dirty字段+提交时配置快照/响应版本，避免覆盖同时变化的其他设置。

现有调用：`MainWindow::requestSnapshot()`→QNetworkAccessManager GET→`handleReply()`→`updateSnapshot()`。动作 `postAction()`先按platform capability及角色映射检查→弹确认→再次检查→`sendJson("POST","/actions",...)`→结果→刷新。保留这次“确认后再次检查”；确认弹窗期间设备/权限可能变化。

### 亮度完整调用链

`BrightnessController::commit(percent)`（新增）→HmiClient PUT/settings保存提交亮度→验证响应settings.brightness等于提交值→POST/actions `{action:"brightness",params:{value:184},confirmed:true}`→现有 `_execute_action`→native `_platform_request("display.brightness.set",{channel:"display0",value:184,confirmed:true})`→runtime `displayBrightness`→验证回读channel/brightness→UI同步实际值。

若settings成功而硬件应用失败，显示“显示设置已保存，背光应用未确认”，保留实际亮度未知/旧值，不伪装成功；重试要由用户操作发起。服务缺失时禁用硬件调节并说明，不在GUI直接写sysfs。

## REQ-API-020 DesktopClient 原生本地RPC

入口：`DesktopClient::request(const QString &method,const QJsonObject &params={})`；`snapshot()`；信号 `snapshotChanged(QJsonObject)`、`feedback(QString)`。QLocalSocket默认 `/run/dshancontrol/desktop/desktop.sock`，可由DSHANCONTROL_DESKTOP_SOCKET配置，服务UID由DSHANCONTROL_DESKTOP_UID指定（默认0），使用SO_PEERCRED校验。服务端当前允许自身UID、HMI401、Web400；Web400仅允许desktop.snapshot且去掉绑定码/私密语音历史。

请求为单行UTF-8 JSON+换行：`{"protocol":1,"method":"desktop.snapshot","params":{}}\n`。当前服务严格只接受这三个顶层字段，**不要自行添加request_id**。一连接一请求/一响应，客户端本地request token用于关联；若新增request_id须做协议升级。服务请求最大65536B，客户端响应最大524288B，不能无限读取。

成功 `{protocol:1,ok:true,result:{...}}`；失败 `{protocol:1,ok:false,error:{code,stage,message}}`。snapshot真实result根为version,cloud,reporting,home,voice；`service_connected`由DesktopClient本地添加，不是服务原始字段。

|method|精确params|用途/成功后行为|
|---|---|---|
|desktop.snapshot|{}|读取并更新共享模型|
|cloud.refresh|{}|刷新设备归属/绑定码；accepted后看快照|
|reporting.configure|enabled:bool,period_seconds:30/60/300|持久化上报配置，需要stateDirectory|
|reporting.send|{}|一次上报；需MQTT在线、非inflight且有good点位|
|home.refresh|{}|同步授权设备|
|home.functions|device_id:string|查询设备实际控制能力|
|home.command|device_id,code,value,command_id,revision,confirmed:true|唯一32位小写hex command_id；revision为当前home.revision|
|voice.command|command:string|start_listen/stop_listen/enter_free_chat/exit_free_chat|
|voice.clear|{}|清会话对话记录，不改变设备|

`dispatch()`成功返回accepted:true表示受理，后续结果读snapshot。前端需新增本地操作完成信号区分传输受理、业务完成，不改变现有wire envelope。not-configured/not-connected/no-data/not-ready/stale-or-denied/read-only/busy等错误映射为准确文案，保留code与stage供诊断。

### 字段绑定

cloud.configured/busy/error/mqtt、cloud.pairing.device_id/ownership/fresh/code/expires_in。仅fresh的bound能显示已绑定；旧值显示上次状态。绑定码有效期用单调时钟倒数，过期清空；重读同一旧码不重新延寿。UI不保存密码/密钥，不从provider私有配置读令牌。

reporting.enabled/persistent/period_seconds/inflight/last_broker_ack/error/points[]；点位含point_id/name/type/value/unit/timestamp/source/quality。有效点数只数good有限值。UTC时间先解析再转本地，不使用字符串mid截取假装时区转换。

home.authorization/fresh/busy/error/revision/devices/functions/pending。设备id/name/online/room/status；functions按device_id映射，每项code/type/values/writable。Boolean只传bool；Integer校验min/max/step和整除步长；Enum只传range中的字符串。pending键为device_id+'/'+code。服务在30秒fresh授权/能力窗口内再次校验，UI不能绕过。

voice.configured/ready/state/history。state idle/listening/thinking/speaking/error；ready依赖录放音/激活/运行时状态。服务已存在5秒heartbeat过期、按住录音30秒/连续对话120秒voiceStopAt兜底逻辑，应核验并沿用；UI仍需TouchCancel/页面离开停止，集成时补测异常断连，不另造假ready。

## REQ-API-030 媒体worker

`MediaSession::start(bool explicitRequest=false)`、`command(QString,QJsonObject={})`、`snapshot()`，信号changed/feedback。worker路径为HMI可执行文件同目录的`dshancontrol-media-worker`，不能假设只放/usr/bin就一定被发现；打包需与当前应用bin目录一致。独立QProcess不是独立Qt窗口，视频层由worker/TPlayer管理。最新MediaPanel已封装文件选择、播放列表、seek/volume/mute/loop和geometry，提供fullscreenRequested(bool)信号；当前hideEvent会close而不是保留暂停。新壳须明确采用本包“离开暂停隐藏”策略时调整该生命周期，不能直接套用旧hideEvent造成状态丢失。

stdin每行 `{protocol:1,request_id:<UUID>,command:<name>,params:{...}}`，stdout为JSON回应/`event:"status"`，stderr为诊断。不同于Desktop RPC，这里已存在request_id，不能混用封装。响应读取上限131072B，客户端队列16、rect合并；不可用清队列，不在worker重启时重放旧open/control。

|command|params|条件|
|---|---|---|
|snapshot|{}|读取状态|
|rect|x,y,width,height|物理屏幕坐标，全为非负偶数且≤8192，宽高≥8|
|open|path,volume|本地绝对普通文件，volume0..100；先有合法rect|
|play / pause|{}|已prepared|
|seek|position_ms|seekable且非seeking，0..duration且≤INT_MAX|
|volume|value:0..100|后端可用|
|mute / loop|value:bool|后端可用；loop为当前worker已有命令|
|visible|value:bool|handle/prepared；遮罩前隐藏|
|close|{}|结束并释放，状态idle|

状态至少available/backend/state/first_frame/hardware_decode_confirmed/position_ms/duration_ms/seekable/seeking，按后端实际字段消费。视频区域1024→实际物理屏后再向内偶数对齐，不能拿逻辑坐标直接发1280屏。若preparing期间visible还不可调用，应推迟显示/close并记录状态，确保弹层不被视频盖住。合成策略需在真实linuxfb/Cedar层序验证，主机PNG不能证明。

## REQ-API-040 原生应用更新与健康心跳

复用 `UpdatePanel`，`requestNative()`通过QProcess调用配置的runtime executable参数 `rpc,method,compactJson`；不自行shell拼接。默认原生执行器`/usr/bin/dshancontrol-runtime`，配置`/etc/dshancontrol/updater.json`及既有环境覆盖。

1. `update.identity {}` 获取system/installed/check_configured。
2. `update.status {}` 恢复现有任务；之后 `{task_id:...}`轮询。
3. `update.start {operation:"check"}`，保存checkTaskId与候选release。
4. `update.start {operation:"download",source_task_id:checkTaskId}`，保存downloadTaskId。
5. 用户确认重启相关服务后，`update.start {operation:"install",source_task_id:downloadTaskId,confirmed:true,version:selectedRelease.version,package_sha256:selectedRelease.package_sha256}`。
6. 展示原生阶段、真实错误、维护拒绝与回滚结果；中断后恢复查询，不重新发install。

继续在GUI事件循环中创建 `ApplicationHeartbeat(file,commit,healthUrl,&app)`；环境变量DSHANCONTROL_HMI_HEARTBEAT / DSHANCONTROL_APPLICATION_COMMIT / HEALTH_URL保持。匹配后端健康响应才更新心跳，不能用另一个后台进程写假活跃。布局/媒体/网络异常不能卡住事件循环。

## REQ-API-050 新增接口的边界

AppRouter、DesktopStateStore、WidgetFactory、PointHistoryStore、OverlayManager、BrightnessController、HmiClient为拟新增/抽取的C++类，具体签名见contracts/proposed-interfaces.h。这些是实施约定，不是虚构现有API。没有新的对外HTTP接口必需项；环境趋势首先本地环形缓存，确需跨重启/远端历史时另定义原生服务版本化契约，不扩展旧Python运行时。
