## 开机两条路径

S60挂载持久分区，S69调用storage-check和initialize并启动runtime，S70启动应用。原生initializeApplication()负责保数据初始化，随后按策略调用applicationPermissions(config,true)；应用启动经系统dshancontrol-services进入startApplication()。

没有current时，验证不可变factory树，逐文件复制到独立stage、fsync并发布factory，再创建current。默认配置只在不存在时写入。离线成像不能代替这条路径的实物验收。

已有current时，initializeApplication()保留既有release和installed身份，不用rootfs内新factory替换它。Web配置、两库、session key、EDS和独立HMI布局均保留。因此只替换rootfs内factory不会使现有板子开机使用新桌面；不能用开机脚本覆盖current或伪造installed.json。

新系统启用native desktop/media策略时，还须核旧应用组件及其在新系统上的回退能力。现有持久factory是旧组合；新系统和新应用不能只验证其中一份。旧应用若不兼容新角色策略，需先完成配套系统恢复/维护迁移方案。不能承诺应用链接回退就能恢复整个系统；这条跨系统路径尚未实测。

## 正式安装接口与顺序

以下为已实现调用链及门禁，不是当前可执行的部署指令：

1. 发布方用build_application_release.py准备负载。要求经审查clean提交、绑定相同commit/HMI/三个组件SHA和target字段的build-info；desktop负载要求明确合格的desktop runtime契约。合法签名在受控发布端完成，私钥不进入设备。
2. 设备核产品/仓库、架构/softfp/libc/runtime_id/协议、允许channel、from_versions、sequence高水位和data_schema。实际旧版本必须显式纳入升级路径；协议v1不支持跨data_schema迁移。
3. 原生install MANIFEST SIGNATURE PACKAGE进入NativeUpdater::install()：固定输入、验签、validateManifest()/matchTarget()、核大小/SHA/空间，安全解包至独立stage并发布release目录；这些准备不等于已切换应用。
4. 系统maintenance钩子通过现场维护验证后，才写transaction和更新高水位。当前/etc/dshancontrol/maintenance-check不存在，不能用空脚本或成功标志替代安全停机/联锁。
5. 依次hook(stop)、switchTo(new)、记录switched、hook(start)、healthy()。r26停止还等待私有media surface lease与合法成功报告，成功后才清HMI receipt；超时或未知所有权拒绝成功。
6. 健康观察通过后提交事务并删除transaction；失败走rollback()，中断走recoverInternal()。恢复失败保留事务和原始错误，不能清记录假装成功。跨系统回退不由应用级事务自动保证。

已有原生停止/启动、PID身份、401→402 IPC和媒体回收有界实证，不包括生产签名安装、整系统掉电回退或完整开机验收。

## 空间与保留规则

NativeUpdater::install()要求可用空间严格大于：package_bytes + unpacked_size + 16 MiB。

用正式payload函数生成的仅尺寸审查负载包含19文件，package10937912字节、展开14241512字节，所需严格大于41956640字节；没有签名manifest，不能安装。

04:15:50Z可用72376320字节，满足这项尺寸条件；空间不是安装授权。此前14475264字节确实不足。六份已结束旧自有HMI在Ubuntu/SDK按SHA去重归档并逐成员复核后离板，释放57937344字节，每个原路径留恢复指针。当前r23d RAM程序未动；全部板端0700私密备份、用户数据、日志、失败和批准PNG保留，未导出。

不能删除私密备份、格式化UDISK、移走当前程序或降低门槛来腾空间。后续空间要重新读取，本次值不是永久保证。

## 未验收条件

- 生产目标字段仍pending，validation=not-run；草稿候选不能直接回写生产。validateTarget()拒绝pending字段；not-run也没有替代资格证据的效力。
- 合法签名来源/设备公钥尚未确认；仓库未跟踪生产公钥或应用发布工作流。不用测试/其他板型密钥，不自行创建信任根。
- 源dirty且本会话禁止新commit/push/release，不能伪造clean build-info或把本地归档称正式更新。
- 维护钩子缺失；整SDK构建空间不足16GiB，UDISK出厂ext4 provision、kernel/bootloader链、物理掉电/回退未验。
- 全局402迁移、现有current与新系统的配套回退、真实云/家庭/语音/现场业务、物理LCD/手指/声音、独立真实86400秒仍待。
- 仍为25PASS/48PARTIAL/0RUNNING。测试数量、截图、fsck或归档校验数不能代替73项完成率。
