# 06 Qt5 架构与开发任务

## REQ-ARCH-001 模块分层

```text
单一QApplication / HMI主进程（保留ApplicationHeartbeat）
 └─ DesktopShell : QWidget
     ├─ StatusBarWidget / FooterWidget
     ├─ QStackedWidget : DesktopCanvas + 各应用Page
     ├─ OverlayManager : ControlCenter / AppDrawer / WidgetLibrary
     └─ EditController + GestureRouter
数据层：HmiClient + DesktopClient + MediaSession → 共享ViewModelStore
功能层：AppRegistry/AppRouter、WidgetFactory、PointHistoryStore、DesktopStateStore
绘制层：DesignTokens、共享IconPainter、CardPainter、TrendPainter、FontLoader
```

主壳建议放components/hmi/src/desktop/，在已有omnigate-hmi.pro显式加入sources/headers/resources。不要让整个预览Desktop类成为生产单文件：抽出画图规则而非复制它的模拟业务。widgets订阅规范化viewmodel，不直接构造HTTP/RPC或操作设备。

桌面7个卡片保留各自 QWidget 或统一canvas均可，但生产与fixture须同一绘制代码、同一排版。可交互输入框/按钮采用真Qt控件，绘制不冒充输入能力；矩形命中与视觉同坐标变换。复杂原应用页保持原Qt布局和信号，挂入shell内容区，必要的高度变化通过布局回归，不能截图贴上当实现。

主UI线程负责事件/轻量模型合并/绘制。网络采用QNetworkAccessManager、QLocalSocket异步，媒体QProcess异步；图片解码/较重数据转换用工作线程，通过queued connection交回QImage。避免频繁重建全部控件和每帧分配整个屏幕的模糊图；不要求全屏实时高斯毛玻璃。缓存静态背景/图标/图片，动态只更新相关区域。任务退出和进程停止不得长时间阻塞GUI。

## REQ-ARCH-002 现有页面改造策略

MainWindow目前buildOverview/buildFieldbus/buildNetwork/buildDevices/buildAlarms/buildSettings是private方法，并管理请求和控件指针。先抽取公共数据客户端，再抽取页面工厂或在MainWindow内保留构建并交给AppRouter；不从外部越权调用private。路由使用稳定字符串id，不使用应用显示名和易变索引进行控制。

`overview→buildOverview`，`fieldbus→buildFieldbus`，`network→buildNetwork`，`devices→buildDevices`，`alarms→buildAlarms`，`settings→buildSettings`。update在现设置页中使用UpdatePanel，可复用同一个实例并从独立route定位，避免两个updater同时轮询/安装。cloud_bind/reporting用CloudPanel不同section，voice/home用FamilyPanel不同section；为这些类补明确选择入口，不能假定已有selectSection函数。video复用最新MediaPanel和其MediaSession，未安装时生成同风格不可用页；MediaPanel当前只有构造函数/fullscreenRequested公开，open/showSection为private，需增加明确路由适配入口。

所有控件关联的capabilityControls、通道过滤、操作确认、QSignalBlocker防止回填触发写入、审计和超时保留。旧页移除外层重复导航/标题时保持内部子tab及字段，不以“新UI暂不支持”为理由删除功能。

## REQ-ARCH-003 构建与资源

字体加入应用资源或随应用share/fonts，启动时明确加载并验证family；包含OFL许可和源manifest。图标由同套QPainter路径供桌面和新面板共享。产品使用的图片为用户绑定资产或应用随包海报，默认fixture图单独标记，避免以设计截图代替正式视频内容。

目标Qt5.11.3/C++11不得使用Qt6-only API、依赖缺失的新模块或高版本标准库。主机可用Qt5.12.8做布局验证；必须用已验证S4专用qmake/sysroot做交叉编译，记录完整工具链/ABI/Qt版本。不得从本机Windows构建输出冒充Linux可执行文件，也不得使用SDK全局错误板配置生成S4包。

desktop-service和media-worker是独立候选原生模块，需补构建、应用包manifest、进程生命周期、UID/目录/socket授权及版本相容测试。若依赖系统层新增启动/权限/库，单独登记系统变更需求，不能偷塞进应用包或以root运行GUI解决。现有T153路径应继续编译/测试，不能把S4媒体库硬绑所有板。

## REQ-ARCH-005 性能与可靠性指标（目标，不是已测结果）

1024×600目标板：已加载状态下点按首反馈≤100ms；纯UI抽屉动画目标≥30fps，无法持续时禁动画保持响应；状态切换不得出现连续500ms主线程卡顿。首次桌面可见目标≤3秒（从QApplication启动计，不含Linux开机）；网络/云失败不拖延可见桌面。记录RSS、CPU和帧间隔实测，不能仅凭主机通过宣称板端达到。

桌面新增常驻内存预算建议≤32MiB（不含已有应用和解码worker）；缓存按绑定图片/可视图表有界。场景循环1000次无持续RSS增长；24小时读状态运行无崩溃/心跳中断；内存不足/图片损坏/磁盘满保持可返回。测量方法和实测数与包中验收表一起填写，未测留NOT_RUN。
