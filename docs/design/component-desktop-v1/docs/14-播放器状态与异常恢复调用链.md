# 播放器状态、异常提示与恢复调用链

本补充对应现有生产 C++ 接口，保持原批准画面的几何、字体、图标、73 项验收标准和十张原始 PNG。异常文案来自真实业务状态；示例预览不是解码、声音或物理屏幕验收。

## 用户操作与函数调用

|操作/事件|现有函数与调用顺序|结果|
|---|---|---|
|打开本地视频|MediaPanel::scan/choose → open(path)；检查可读普通文件且非符号链接 → session.start(true) → geometry() → session.command("open", path/volume)|显式启动或恢复服务，先确定显示矩形再打开文件|
|绑定组件视频|MediaPanel::selectFile(path)；检查规范绝对路径/可读/非符号链接 → start(true)|选择绑定文件，不自行播放其他文件；用户点击播放|
|启动服务|MediaSession::start(explicitRequest) → QProcess::start，4000ms startupDeadline|已有进程不重复启动；失败后没有隐式重启|
|命令发送|MediaSession::command → queue → flush|最多16个待发请求；仅available=true发送；只合并相邻队尾rect，不能越过open等控制命令|
|状态上报|QProcess::readyReadStandardOutput → MediaSession::read → changed(status) → MediaPanel::apply|协议1/合法状态/能力检查；GUI按真实状态更新，不用示例状态覆盖|
|隐藏/退出|MediaPanel::hideEvent与MediaSession析构；close异步发送，1500ms terminate/2500ms kill针对该次进程|GUI不阻塞等待厂商解码器；隐藏不应隐式继续播放|
|受管理停止HMI|原生 application-stop → 配对媒体回收租约/报告检查 → 应用退出|回收确认前保留HMI管理凭据；配对guardian只处理自有视频层，不重置显示/USB/整板|

实现位置：components/hmi/src/mediapanel.cpp、mediasession.cpp；视频worker与guardian位于components/media/src；原生停止契约见仓库runtime实现及13号持久交付文档。

## 中央显示区判断顺序

先判断明确未安装，再判断启动中，再区分服务错误与已知解码能力缺失：

|输入状态|中央主提示|说明/后续|
|---|---|---|
|state=not_installed|播放器组件尚未安装|请安装匹配的桌面应用组件|
|state=starting_service|正在启动播放器|等待播放组件就绪，不能误写成缺少解码支持|
|state=error，available=false，backend不是明确unavailable|播放服务暂不可用|请重新选择视频后重试，不会自动重试|
|state=error，available=true|这个视频暂时无法播放|解码或显示未完成，请检查文件与播放状态|
|available=false且backend明确unavailable（包括error）|播放组件尚未就绪|当前构建或运行环境未提供解码能力；不得误导为重新选文件就能补齐编译能力|
|state=preparing/starting且available=true|正在准备视频|等待解码器返回画面|
|state=paused/prepared|播放已暂停|点击播放继续，进度已保留|
|state=completed|播放结束|选择视频或重新播放|

可见视频层还必须满足真实first_frame、active/visible等条件；错误和覆盖态不能留下透明窗口透出旧视频。上述消息顺序不修改控制按钮的能力判断和协议字段。

## 错误与恢复边界

MediaSession的process error/finished会清除待发队列并发布error/available=false；这些消息没有证明“解码器未编译”。服务曾成功播放后退出，不能继续显示“当前构建无解码能力”。

read()限制131072字节累计响应、协议1、枚举状态及suspend-during-prepare/visibility-state能力；非法/过大/启动超时进入abortWorker，清队列并只结束该次进程。迟到数据不能触发后续运行的错误回收。

错误后必须由用户重新选择本地视频产生start(true)，不能定时自动重试、换播其他文件或误触应用抽屉。测试若自动注入输入，须先确认当前页面；发生未识别输入则中止后续坐标操作。

配对guardian的进程身份、租约和视频区域必须与该次worker一致。异常SIGKILL与卡死SIGSTOP分别保留实际证据；“视频层关闭/缓存归零”不等于完整CMA回收、声音或物理LCD通过。

## 已有证据与未验收范围

r26 H实际播放→服务异常→看图后显式重新选本地文件→新worker首帧→原生停止/重启通过，且发现旧文案缺陷。r27修正文案后，主机既有媒体边界测试7/0/0；正常QtB的实际ARM内置检查27项、十图RGBA完全一致。r27真实异常恢复单独执行和归档，不能借用H旧HMI结果。

正式签名安装、跨启动的原生402角色、真实外部业务、物理触摸/LCD/声音及独立86400秒长稳仍按原清单验收。临时验证结束恢复r23d并不代表r27成为开机版本。
